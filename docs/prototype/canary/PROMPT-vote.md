Ты — второй, независимый аналитик канареечного прогона прототипа `dsgvo-check`. Репозиторий — текущая директория. **Код и данные не меняй**, по сети ничего не запускай. Контекст прогона, файлы и источник истины — те же, что в `docs/prototype/canary/PROMPT-triage.md`. Прочитай его. Прогон: `canary/results/{{RUN}}/`.

Другая модель ({{OTHER}}) разобрала зону «{{AREA}}» и выдала находки. Они лежат в файле `{{FINDINGS_FILE}}`. Проголосуй по **каждой** находке. Проверяй по данным прогона и коду, не по тексту находки: открой названные сайты, `report.json`, `snapshot.json`, `scan.log` и строки кода.

- `accept` — дефект подтверждён в данных и коде, исправление разумно. Если у тебя есть поправка к исправлению, напиши её в `reason`.
- `reject` — не подтверждается. Например: сайт действительно так себя ведёт; это упрощение BRIEF; поведение требует спецификация; цифры неверны; корень в другом месте и исправление ничего не даст. В `reason` — конкретное доказательство.
- `verify` — правдоподобно, но по данным прогона это не доказать. В `reason` — какой эксперимент это решит.

`fixClass` — твоя оценка класса: `code-bug`, `data-catalog`, `spec-question` или `by-design`. Если находка дублирует другую из того же файла, укажи её `id` в `duplicateOf`, иначе `""`. `reason` — по-русски, 1–4 предложения с доказательством (файл:строка, siteId, JSON-путь). Финальный ответ — JSON по схеме.
