Ты проверяешь одну находку ревью исправлений прототипа `dsgvo-check` (раунд по канарейке `20261030-canary2`). Рабочая директория — корень репозитория. Задача — **опровергнуть** находку. Если опровергнуть не удаётся, подтверди её воспроизведением.

## Находка

```json
{{FINDING}}
```

## Как проверять

1. Прочитай код в `file` и вокруг него. Сверь сценарий `failureScenario` с источником истины: `AGENTS.md`, `docs/03-checks.md` (реестр §2.1), `docs/consensus/README.md`, `docs/prototype/CONTRACTS.md`, `docs/legal/wording-guide.md`, `canary/results/20261030-canary2/triage/consensus.json` (группа `gid`).
2. Воспроизведи на текущем коде.
   - Короткий скрипт: `node --input-type=module -e "import { … } from './src/….ts'; …"`. Node 24 сам снимает типы.
   - Или временный тест `{{TMPTEST}}`, который проверяет правильное поведение и потому падает на текущем коде, если находка верна. Запусти `corepack pnpm vitest run {{TMPTEST}}`.
   - Браузерные сценарии — через локальный сервер фикстур, как в соседних интеграционных тестах. В интернет не ходить.
3. Удали временный тест. Если каталог `_review` опустел, удали и его. **Другие файлы не меняй.**

## Вердикт

- `confirmed` — воспроизведение показало неверный результат на текущем коде, или дефект следует из кода однозначно и ты это объяснил.
- `refuted` — сценарий невозможен (назови строку, которая его отсекает), поведение соответствует источнику истины, или находка про открытый вопрос к заказчику из `docs/prototype/canary/TRIAGE.md` §3 и §5.
- `uncertain` — не удалось ни воспроизвести, ни опровергнуть.

`reproExecuted` равно `true`, только если ты действительно запустил скрипт или тест. В поле `repro` приведи команду и ключевой вывод. `fixHint` — минимальное исправление для подтверждённой находки. `severity` — твоя оценка: `blocker`, `major` или `minor`. Без siteId и доменов сайтов корпуса. Тексты по-русски.

Выход — JSON по схеме `docs/prototype/canary/verdict.schema.json`.
