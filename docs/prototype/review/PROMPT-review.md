Ты — независимый ревьюер кода прототипа `dsgvo-check` (пассивный CLI-сканер DSGVO/безопасности на TypeScript 7 + Playwright 1.64, Node 24). Репозиторий — текущая директория. Код НЕ меняй (sandbox только на чтение).

Контекст: `docs/prototype/BRIEF.md` (объём и упрощения прототипа), `docs/prototype/CONTRACTS.md`, `docs/prototype/STATUS.md`, источник истины по поведению — `docs/consensus/README.md` (§2, §4, §5 и блок «Поправки после верификации») и `docs/03-checks.md` (реестр вариантов §2.1). Код: `src/**`, данные `data/**`, тесты `test/**`, доставка `Dockerfile`, `action.yml`, `templates/**`, `.github/**`.

Найди реальные дефекты, а не стилистику:
1. Корректность: логика проверок против спецификации (варианты, уровни, понижения, inconclusive), gate/коды возврата (таблица §5.2), fingerprint, assess (кэп по confidence, routing), derive (третья сторона, first-party proxy, идентификаторы), коллекторы (гонки, таймауты, утечки процессов/профилей, ожидание «тишины», обработка ошибок → правильный статус/диагностика).
2. Безопасность и приватность: SSRF (что не покрыто), редактирование значений cookies/storage/query/mailto, XSS/инъекции в HTML/консоли/Summary, sandbox (chromiumSandbox для require), UA по D10, лимиты частоты.
3. Тесты: проверки без пар violation/clean/inconclusive, тесты, которые ничего не утверждают, флейк-риски, пропущенные негативные случаи.
4. Расхождения с поправками раунда 4б, которые прототип обязан взять (README §2а / errata): контракт адаптера extract/act/verify с классификацией в core, полная CSP HTML, `--proxy` только http://, UA из navigator.userAgent или шаблона (не browser.version()), chromiumSandbox: true при require, скриншот первого экрана без автопрокрутки, относительные пороги TLS-02, checkIP для IP-целей.

Для каждой находки — конкретный файл и строка, сценарий отказа (вход → неверный результат), исправление. Не больше 40 находок, сначала самые серьёзные. id — `S-01`, `S-02`, …; summary и fix — по-русски. Финальный ответ — JSON по схеме.
