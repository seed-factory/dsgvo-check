## 1. Что работает

### Конвейер

`validate → preflight (DNS + SSRF) → http / tls / dns параллельно → browser (A, B, C) → снимок → derive → проверки → assess → gate → отчёты`

- **Повтор по снимку.** `--save-snapshot` и `--from-snapshot` воспроизводят отчёт без сети. Значения cookies, Web Storage и TC-String в снимок не попадают (D20). Target в снимке и отчёте очищен, сырой URL есть только у коллекторов (S-04); заголовки ответа хранятся через один нормализатор с allowlist значений (FP-08).
- **Evidence по 5.3 (схема 0.2.0).** У `request` — `delivery`, `result`, `provenance`, монотонный `tMs` от `scan.startedAt` (одна шкала для всех фаз и коллекторов), `navigationId`, `actionId`, `frameId`, `parentRequestId` и `features` (`identifier {kind, param}`, `matchesStoredIdentifier`, `eventType`, `consentSignal`, `parserVersion`, `observationSource`). Cookie и storage — на той же шкале.
- **Отчёты.**
  - JSON проходит Ajv по `schema/report.schema.json` (zod 4, JSON Schema 2020-12).
  - HTML — один файл без JS, полная CSP (`default-src 'none'`, `img-src data:`, хеш стиля, `base-uri`/`form-action 'none'`); скриншот баннера встроен как `data:`.
  - Дисклеймер с условными абзацами (скриншоты, баннер, бот/гео, регион, прокси, sandbox, неполный скан, фаза C, черновик, Nutzungshinweise) — в JSON, консоли, HTML и Summary, а также в отчёте, который возвращает `scan()`. `--help` и `README.md` содержат Nutzungshinweise.
  - Консоль и Job Summary.
  - Строк `T[0-9]_` нет нигде, кроме JSON.
- **Коды возврата** — по таблице 5.2. Они проверены на уровнях L1, L2 и L3, включая собранный CLI и образ Docker. После ревью: `--strict` действует при `--fail-on none`, `maxSeverity` без кэпа confidence, глобальный timeout до стартовой фазы A — fatal `timeout`, после abort коллектору дают 10 с вернуть собранное.

### Фазы браузера

| Фаза | Состояние |
|---|---|
| A | До 6 страниц: старт, Impressum, Datenschutz, Kontakt и до 2 по ключевым словам, навигации или sitemap. Для дополнительных страниц соблюдается `robots.txt`. Тишина по D09, пауза между навигациями ≥ 1,5 с, потолок 2 000 запросов. Если правовой ссылки нет — переход через Kontakt, затем фолбэк `/impressum`, `/datenschutz`. Документы разбиваются на разделы с manifest полноты. |
| B | Наблюдение ≥ 4 с, распознавание CMP, ожидание позднего баннера (≤ 5 с), первый экран и скриншот по D20 (`page.screenshot({clip})`, без прокрутки), «Ablehnen» — адаптер исполняет цель `plan.click` из `classifyFirstLayer` (`act(page, action, target)`), verify, reload, второй verify, 2 контрольные страницы. Момент клика — доверенное нажатие в странице. |
| C | «Alle akzeptieren» по той же логике и 2 контрольные страницы. Пропускается, если в B CMP не распознан. |
| A′, M | Не реализованы (упрощение BRIEF). |

Каждая фаза запускается в свежем `launchPersistentContext(tmpdir)` (Chrome for Testing, new headless). Sandbox по умолчанию `require` (`chromiumSandbox: true`). UA — `navigator.userAgent` плюс токен D10. Перегрузка (D09): 429/503 на любой навигации или ≥ 3 таких ответа за фазу → пауза по `Retry-After`, один повтор, затем новые навигации к хосту не начинаются, `SCAN-THROTTLED`; проверки — `partial`, а без оцениваемой страницы A — `inconclusive (throttled)`.

## 3а. Канарейка-2 (`20261030-canary2`)

Измерение сканера на сборке после ревью, не приёмка (консенсус §2а). 100 сайтов, замороженный `dist`; результаты лежат локально в `canary/results/` и в git не попадают (AGENTS п. 7), ниже и в [canary/TRIAGE.md](canary/TRIAGE.md) только агрегаты. Процесс: разбор по пяти зонам (Claude Fable 5.1 и Codex GPT-6.1-Sol), перекрёстное голосование, модератор с критиком, исправления по зонам, интеграция. Из 65 групп: 39 `fix`, 10 `verify-then-fix`, 9 вопросов к спецификации, 7 отклонено.

**Агрегаты исходного прогона:**

- Сканы: 88 `complete`, 5 `partial`, 7 `failed` (6 раз `start-page-blocked`, 1 раз `scan-timeout`); коды возврата 0 — 93 сайта, 2 — 7 сайтов.
- Диагностики (сайтов): `SCAN-BLOCKED` 10, `SCAN-TIMEOUT` 2, `SCAN-THROTTLED` 1, `SCAN-PRIVATE-REQUEST-BLOCKED` 1.

## 5. Известные пробелы

- **Браузер.**
  - Нет фаз A′ и M.
  - Нет перехвата pagehide-маяков, preconnect без запроса, CDP `blockedCookies` и initiator.
  - Нет дополнения DSE в фазе B (D15): аккордеоны не раскрываются кликом, ленивые части дают `complete: false`.
  - 5.3: `provenance` различает только `network` и `service-worker` (кэш не определяется); связь запроса страницы, обслуженного SW, с upstream-запросом самого SW (`parentRequestId`) не строится — только редиректы.
  - Сообщения исключений Playwright в `PhaseRecord.errors[].message` не проходят редактирование URL (FP-09 не воспроизведён: известные пути с URL навигации сохраняют только код ошибки).
- **CMP.**
  - Адаптеры не сверены с живыми установками, кроме одного Borlabs: формы Usercentrics v3, недокументированный API CCM19, объект RCB, классы overlay у Borlabs.
  - Гео- и бот-сигналы есть не у всех CMP.
  - Accessible name упрощённый, закрытый shadow DOM не поддерживается.
  - Веса эвристики не откалиброваны.
- **Проверки.** PRIV-02, P1 (кроме CONSENT-05), P2, baseline, подавления, JUnit и PDF не реализованы: поля в схеме есть, логики нет.
- **DNS.**
  - Организационный домен определяется по PSL (tldts).
  - Обход останавливается на первом имени с DMARC-подобной записью.
  - Анализ SPF статический.
  - Нет DKIM и `rua` на чужой домен.
- **HTTP/TLS.**
  - Проверяется только первый адрес из lookup.
  - Нет `--use-system-ca`.
  - За прокси вердикт TLS по хопам неизвестен.
- **После разбора канарейки-2.**
  - Телефонные номера в свободном тексте не маскируются (`redactText` трогает e-mail, `mailto:` и URL); решение заказчика.
  - Имена ключей Web Storage и cookies могут содержать значение, похожее на идентификатор посетителя; правило редактирования не утверждено (G05).
  - CMP, распознанный адаптером (`high`), но ни разу не показанный: причину скрытия (бот-ветка, гео, поведение вендора) без лаборатории D23/L4 не проверить (G11).
  - `chainComplete` в TLS-endpoint считается как «authorized или самоподписанный последний сертификат»; разрешимость издателей через присланную цепочку и trust store не реализована. Ложный `chain-incomplete` при `authorized = true` устранён (G40); `chain-incomplete` выдаётся, только если сервер не прислал издателя leaf, иначе TLS-02 даёт `certificate-invalid` (R20). TLS-01, HDR-01 и `tlsBlocked` в `scan.ts` читают только код ошибки и считают такую цепочку неполной, то есть работающей; браузер сам останавливается на `ERR_CERT_*` (`tls-blocked`). Согласовать их с TLS-02 можно, передав признак присланного издателя; не делалось.
  - TLS-01 при редиректе на другой хост без HTTP-пробы финального хоста даёт `partial`; дополнительные HTTP-пробы не добавлялись (G43). Разбор объединённых полей XFO и HSTS проверен на L1, на настоящем HTTP/2 — нет (G41).
  - Приоритетный проход ссылок ограничен 2×`maxLinks` (3000), список ключей в `in-page.ts` самодостаточный и только предварительный: лексикон `data/legal/links.yaml` из страницы недоступен (G04).
  - `ScreenshotRecord` не хранит `crop.box`; `DocumentRecord` не хранит исходный атрибут `lang` (только язык по маркерам).
  - Осиротевший Chromium после SIGKILL родителя может пересоздать каталог профиля без маркера уже после уборки; он удаляется правилом «старше 24 ч» (G57).
  - Живых прогонов после исправлений коллекторов (privacy, CMP-ожидание, документы, SCAN-BLOCKED, профили, L1–L3, ревью Codex Sol S-*) не было: пересчёт по снимкам (`--reanalyze`) видит только изменения проверок, derive и каталога. Целевой пересчёт 15 сайтов шёл до ревью исправлений и до L1–L3.
  - Повтор навигации к стартовой странице (L2) виден в `PhaseRecord.errors` и в логе, но не в отчёте: нет поля `PageVisit.attempts`, `environment.requestsIssued.navigations` занижен на число повторов. Такой же тихий `pages.pop()` остаётся в повторе 429/503 (`navigate()`) и в повторе стартовой для фаз B и C. Контракт отчёта не менялся (вопрос заказчику, TRIAGE §8).
  - Таймаут и 5xx стартовой «дважды» (02-architecture §12, 03-checks §7.4): код повторяет любую ошибку навигации кроме `ERR_CERT`/`ERR_SSL`/`ERR_BLOCKED`, интервалы повтора и таймаут навигации 30 с не согласованы (TRIAGE §8).
  - Расхождения документов спецификации с кодом после ревью (в том числе `footer-covered-by-banner` в 03-checks: перекрытая правовая ссылка — это ссылка по лексикону `data/legal`, S-cmp-2), документы под код не переписывались: `SCAN-PRIVATE-REQUEST-BLOCKED` при полностью компенсированном отказе молчит, при частичном называет `recovered` (R28; 03-checks §7.8, wording-guide §5.19); таблица wording-guide §5.5 и 03-checks §3.7 для TRACK-01 (R07); правило ранга CONSENT-04, адаптер выше эвристики только при `high` (R23; консенсус §5.5); текст fix консенсуса G18 про header/footer (R02).
  - После ревью Codex Sol (TRIAGE §9, открытые вопросы):
    - S-cmp-1 (uncertain, не исправлялась): исключение неизменной denied-категории против обхода G14; нужна лабораторная проверка конфигурации CMP.
    - Маска адресов не закрывает закодированный адрес в обычном тексте вне URL и `mailto:` (`alice%40example.invalid` между словами) и домен-литерал `user@[192.0.2.1]`; имена query из allowlist без правила значения (`family`, `hl`, `display`, …) хранят любое значение без адреса. Решение владельца контракта.
    - `TrustStore` из двух значений не различает хранилище OpenSSL (`--use-openssl-ca`, помечено `system`); конфигурационные файлы Node не разбираются.
    - Ветка JS-редиректа HTTP-коллектора читает инертные скрипты (`<template><script>location.replace(…)`); значения CSP: источник из одной метки с путём без `@` и `%2540` без пути остаются как пришли.
    - `removeStaleProfiles` считает маркер без `host` локальным (проверка pid); `launch.ts` пишет `host` всегда, такие маркеры только от старых версий.
    - `h1`, заголовки и свёрнутые панели в обёртках `sticky-footer`, `fixed-header`, `section-footer` остаются хромом: Impressum без маркера в `title` даёт `unconfirmed`, а не `found`; при ≥ 200 ссылок под сплошной подложкой CMP-проба не просматривает хвост DOM.
    - Первая блокировка при успешном повторе (S-robustness-3) видна только в `PhaseRecord.errors`, в отчёте попыток нет (см. выше, `PageVisit.attempts`); код `ETIMEOUT` резолвера выводится в тексте `SCAN-PRIVATE-REQUEST-BLOCKED` как есть.
    - Тест `robustness-pages` (G55, LEGAL-01) один раз упал в полном параллельном прогоне: `missing:browser` за 63,8 с, вровень с тайм-аутом запуска Chromium 60 с в `launch.ts`; в одиночку 3 из 3 и дважды в полном прогоне зелёный. Причина не доказана, ретрай не добавлялся.
  - Девять вопросов к заказчику (spec-question) без решения: G05, G12, G29, G30, G38, G39, G45, G47, G53 — [canary/TRIAGE.md](canary/TRIAGE.md).
- **Прочее.**
  - Коллекторы не знают `dataDir`: лексикон CMP в коллекторе всегда берётся из пакетных `data/cmp`.
  - `CONSENT-02.cmp-cookie-with-uid` объявлен, но не выдаётся: нужен безопасный признак UID в consent-cookie.
  - Docker-тест L3 для недоступной цели делает настоящий DNS-запрос `does-not-exist.invalid` (только при `DSGVO_E2E_IMAGE`).
