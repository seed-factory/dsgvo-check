# Перекрёстное ревью архитектуры — Codex GPT-6.1-Sol

Дата: 2026-10-30. Исходный автор: Claude Opus 5.5. Исправлен [docs/02-architecture.md](../../02-architecture.md). Источники решений: `specs/*.md`, [консенсус с поправками раунда 4б](../README.md), [errata](../round-4/errata.md). Приоритет ТЗ над консенсусом сохранён; ответы заказчика не предполагаются.

## Что изменено

- **Введение, §1–3:** указан приоритет источников и отделён целевой релиз от среза прототипа (§2а консенсуса). Исправлены ссылки на реальные ADR-0001/0004 вместо номеров кандидатов. Кандидат ADR-033 не выдаётся за принятое решение: supply chain помечен предложением, добавлен ОВ-25. pnpm — 12.16.1 через `packageManager`, запасной 11.28.9 после smoke. Чтение конфига и запись снимка больше не названы чистыми операциями; срез проверки — `SnapshotSlice<K>`, а не несовместимый с ключами через точку `Pick<Snapshot, K>`.
- **§4.2, §7, §17:** пять фаз в четырёх свежих профилях A (A′ в конце), B, C, M; исправлен расчёт запусков. До 16 основных навигаций отделены от повторов, редиректов и дополнения документов. Числа запросов и дополнительных действий остаются в `plan`/coverage.
- **§4.2:** `require` явно включает `chromiumSandbox: true`, без `--no-sandbox`. Описаны npx, выдача seccomp-профиля образом и точная инструкция повторного Docker-запуска, подключение профиля Action и явный `off` в GitLab. Конфликт с запуском одной командой отослан к вопросу 8; доступность sandbox не объявлена доказанной без С3. Основание `acceptDownloads: false` — D25.
- **§4.2, §8.6:** DSE собирается в A без кликов и независимо от отказа; после подтверждённого отказа B дополняет документ раскрытием секций. Добавлены manifest и `banner-open`; полный документ не становится автоматически `inconclusive` из-за CMP. Ради документа согласие не нажимается. LEGAL-01 может найти PDF, хотя PRIV-* его не оценивают.
- **§4.2, §11.5:** снимок viewport через `page.screenshot()`, до действия, с последующим crop по `box`. Единое правило для адаптера и эвристики: однозначный контейнер ≤ 50 % viewport; иначе `screenshot-skipped`. Полный кадр не пишется в артефакты. Уточнены CSS-координаты, `scale: 'css'`, `crop {box, viewport}` и геометрия фреймов. В Messumgebung и Nutzungshinweise указано раскрытие IP третьим лицам в фазе C.
- **§4.3, §6.1–6.4:** единый `EgressPolicy`: resolve → проверить все A/AAAA → соединиться с проверенным IP без повторного резолва. Покрыты прокси, undici, `node:tls`, `net.Socket`; редиректы и новые соединения тоже проходят политику. Уточнены HTTP forwarding и CONNECT, а также то, что CONNECT не раскрывает HTTP/2-запросы и их результат.
- **§6.4, CLI:** upstream в 1.0 только `http://`; SOCKS5 перенесён в бэклог. Upstream получает `CONNECT <проверенный IP>:<port>`, IPv6 в квадратных скобках, исходные Host/SNI сохраняются внутри туннеля. Отказ принимать IP-литерал — ошибка без hostname-fallback. Локальный адрес назначения не выдаётся за подтверждённый peer upstream; сеть/ACL/NAT upstream вне гарантии. Выбор CDN-узла локальным резолвером — limitation. DNS напрямую и `egress.collectors` — принятое решение, ОВ-7 закрыт; противоречащая upstream-часть удалена из ОВ-8.
- **§4.3, §6.3, §12, §17.3:** общая политика 429/503 для навигаций и проб: три ответа целевого хоста за фазу либо ответ на навигацию, для проб три подряд; `Retry-After` ≤ 30 с, один повтор, затем прекращение новых обращений к хосту, `SCAN-THROTTLED`, неполное покрытие. Лимиты тела требуют потокового чтения и отмены, одного Range недостаточно.
- **§4.4:** TLS через `EgressPolicy`; DNS-имя — SNI/`checkHost`, IP-цель — `checkIP` без SNI. Добавлены `lifetimeDays`/`ipTarget` и относительные пороги срока: min(14 дней, 25 % L), min(30 дней, 50 % L), исключение для приближающегося истечения при L ≤ 10 дней. Уже истёкший короткий сертификат остаётся невалидным. Отделены диагностическое чтение сертификата и запрет обхода TLS-ошибки браузером; отсутствие root в серверном наборе не объявляется неполной цепочкой. Для TLS-04 ограничиваются обе границы версии, ServerHello не назван завершённым handshake.
- **§4.5, §7.6–7.7:** исправлены Node DNS API/нормализация ошибок; UA берётся из CfT `navigator.userAgent` с заменой `HeadlessChrome/` либо из шаблона с major. M использует мобильный шаблон и согласованные metadata; TLS не несёт UA. Вместо общего «проверить все CMP» внесена статическая таблица: совпадают только isbot/RCB; С1 подтверждает её в рантайме и отдельно проверяет Usercentrics/CCM19/CookieHub и ленивые чанки. TCF `ping` исправлен на callback-вызов v2: он не возвращает consent-категории и не доказывает ответ пользователя. Гео-сигналом является явное out-of-region-значение, не существование API.
- **§8.1–8.3, §16.2:** адаптер сведён к `extract / act / verify`; решение остаётся у `classifyFirstLayer`. В `CmpFacts` есть геометрия, actionability, контраст, `vendorRole`, блокировка, состояние, гео/бот-сигналы. `CmpId` перенесён в пример core API, чтобы core не зависел от collectors; согласованы `ConsentState`, `ViewportSpec`, `Box`. `ButtonRef` сериализуем, не Playwright Locator; конкретная форма вспомогательных типов отмечена ОВ-16.
- **§8.5, §13.5:** autoconsent не копируется и не модифицируется; read-only-детект использует собственные правила зависимости. optOut/optIn/cosmetic и любые мутирующие действия выключены; точный конфиг 17.1.0 оставлен под ⚠. Добавлен контракт `THIRD_PARTY_NOTICES` в npm/OCI, MPL-2.0 с исходником точной версии, GHSA CC BY 4.0, Apache NOTICE, `datasets[].attribution`, HTML-атрибуции и L0-проверка полноты.
- **§8.7–8.8, §10:** `blocking-no-reject` требует `acceptAvailableAtFirstLayer`; добавлен `no-choice-at-first-layer: info`. Неизвестные CMP-варианты `locked: true`, `gating: false`; override на них даёт `invalid-input`, инвариант нельзя снять YAML. В примере ruleset согласованы вложенность и чтение severity после нормализации. Подтверждение отказа требует `ready`/`denied`, `origin: action` после клика, `stored` после reload и `decision.responded: true`; default-denied не считается отказом. Переход через Einstellungen из прежнего ОВ-14 убран из текущего контракта как противоречащий D12.
- **§5, §9–11:** отдельный `observationId` удалён; связи через общие `evidenceIds`/`evidence[].id` и `related[]`. Вместо request.state — `delivery / result / provenance`; добавлены единая монотонная шкала `tMs`, navigation/action/frame/parentRequest-связи, безопасные `features` с видом идентификатора, сравнением со storage, событием, consent-сигналом, версией парсера и источником наблюдения. Устойчивый ID отделён от per-load-числа. Связь SW/upstream не подменяется одним запросом; `request.frame()` может быть недоступен. Сеттер storage не доказывает принятие. Время клика отделено от завершения Playwright `click()`.
- **§11:** уточнены `scan.options.overrides[]`, attribution, consent decision и TLS-поля; везде одно имя `ruleset.version`. `VULN-02 not_applicable` — только без всех поддерживаемых компонентов. Таблица `subject` дополнена для TLS-01/02/03/04, SEC-01, LEGAL-02, ADMIN-01, BFSG-01, PERF-01. Удалена противоречащая таблице идея обязательного префикса каждого subject; открыта только сериализация составного ключа.
- **§12:** спор D03 указан 2:1:1 с решением модератора. Релевантность — статический максимум после ruleset/overrides без confidence cap. `none` допускает fatal/strict `2`; ранний timeout на старте — fatal `timeout`, поздний зависит от оставшихся проверок и находок. Добавлены браузерные 429/503, все входы гейта, `--checks` в CLI. GitHub warning/Summary отделены от GitLab stderr/JUnit `<error>`; цена мягкого режима указана явно.
- **§1.3, §12, §14:** JSON сначала страховочный, после репортёров атомарно перезаписывается с окончательным кодом. Ошибка любого запрошенного формата даёт `report-write-failed`; отдельно описана ошибка самой перезаписи. CSP разрешает data-изображения и единственный хешированный style, запрещает base/form; `style=` нет. JUnit приведён к согласованному маппингу, включая `not_applicable`, system-out и properties; ОВ-17 оставлен только для умолчаний/композиции отчёта.
- **§11.10, §15:** `baseline migrate` удалён из 1.0; несовместимая fingerprintVersion — ошибка. **§5.5, §11.9, §17.4:** чистому гейту передаётся время проверки подавлений; воспроизводимость технической оценки не смешивается с текущими expires, временем выполнения или отсутствующими онлайн-VULN-данными. **§13.5:** компиляция собственных YAML не исключает runtime-парсер пользовательского YAML. **§16.3:** будущий PageProbe помечен предложением и вынесен в ОВ-26.
