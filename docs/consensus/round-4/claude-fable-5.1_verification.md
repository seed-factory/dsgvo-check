# Раунд 4 — независимая верификация `docs/consensus/README.md`

Верификатор: Claude Fable 5.1 · Дата: 2026-10-30

Прочитано целиком: `docs/consensus/README.md`, `specs/dsgvo-check_TZ.md`, `specs/dsgvo-check_katalog-proverok.md`, `specs/dsgvo-check_idea.md`, все четыре `round-3/*_critique.md`, `round-3/votes-matrix.md`. Точечно: `docs/01-research/browser-automation.md` §3.2–3.4 и §10, `regulatory-landscape-2026.md` (таблица решений судов), `data-sources-and-licenses.md`, `engineering-ci-distribution.md`, `http-dns-tls-mail.md`. Факты проверены по npm registry, nodejs.org, GitHub (browsers.json Playwright 1.64), docs.gitlab.com, rfc-editor.org, letsencrypt.org, docs.docker.com. Непроверенное помечено «⚠ проверить».

Общий вывод: README передаёт голоса в основном верно, таблица ошибок §6 сверена с критиками и совпадает по атрибуции. Найдены два блокера (контракт адаптера CMP противоречит собственной архитектуре; умолчание `--sandbox require` не согласовано с ТЗ «одна команда без конфига» и с путём «через Docker-образ»), пять крупных проблем (искажение голоса Terra по D08, недоучёт уже измеренных регулярок CMP в D10/вопросе 3, ложные `warning` TLS-02 на короткоживущих сертификатах, неисполнимое «`--proxy` на все коллекторы» и дыра в SSRF-политике для сырых сокетов, отсутствие среза минимального прототипа) и ряд мелких неточностей.

## 3. Обязательные правки до архитектуры и прототипа

1. **Контракт адаптера CMP (№1).** Переписать D12 и ADR-014: адаптер — `extract / act / verify`, решение о классах кнопок и блокировке — только в чистой `classifyFirstLayer` core; `plan.click` фиксирует выбор. Без этого архитектура повторит ошибку §6.1 №1.
2. **Sandbox на трёх входах ТЗ (№2, №9).** Описать поведение `--sandbox require` для `npx`, `docker run` и CI; расширить С3 на plain `docker run` и AppArmor Ubuntu ≥ 23.10 (включая GitHub `ubuntu-24.04`); исправить объяснение про moby; вынести конфликт с «одной командой без конфига» в вопрос 8 явно.
3. **Единая `EgressPolicy` вместо «прокси для браузера и undici» (№6).** Проверка IP при соединении — для браузера (через прокси), undici, `node:tls` и `net.Socket`; `--proxy` в 1.0 только HTTP CONNECT; DNS-коллектор — прямой `--resolver`, записанный в Messumgebung. Убрать «на все коллекторы».
4. **Срез прототипа (№7).** Добавить раздел «Прототип (этап 1)»: фаза A, 4 проверки из §4 со штампом «1», `gate()`, JSON, консоль, SSRF через `--host-resolver-rules`/`lookup`; прокси, B/C/M, baseline, `en`, JUnit/Summary — после. `baseline migrate` и SOCKS5 — бэклог; `en` в тесте полноты необязателен.
5. **TLS-02 относительно срока действия (№5).** Заменить абсолютные 14/30 дней на порог от общего срока сертификата; 6-дневные сертификаты не дают находки; добавить фикстуру clean и строку в вопрос 9.
6. **Верность голосов D08 (№3), а также D06, D13, D18, D26, D27 (№18–21, №28).** Terra-К поддерживает «вход + общая контрольная подвыборка» → D08 «большинство 3:1»; остальные уровни согласия уточнить по матрице.
7. **D10 и вопрос 3 на основе таблицы ресёрча (№4).** Записать, что статически буквальный UA ловят только `isbot` и RCB; сузить риск 1; переформулировать С1 как подтверждение и проверку Usercentrics/CCM19/CookieHub; добавить запрет `bot|crawler|spider|robot` в имени организации и репозитория.
8. **Согласовать списки вариантов и ruleset (№10, №23).** `consent-without-action` — в D13/ADR-015; в вопрос 9 добавить MAIL-02 (`~all` + DMARC), EMBED-02…05 при T1, пороги TLS-02.
9. **Мелкие технические поправки перед написанием ADR (№11, №13, №14, №15, №16, №25, №26).** A′ в профиле A; разделить GitHub/GitLab в «мягком режиме»; перечислить все входы гейта; правило скриншота для эвристического кандидата; фолбэк `documents` при открытом баннере; UA по шаблону; ADR-033 либо в D24, либо как предложение.
