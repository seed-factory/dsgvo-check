# dsgvo-check — проект решения (раунд 2, Claude Fable 5.1)

Входные данные прочитаны полностью: идея, ТЗ, каталог, выжимка раунда 1, критик полноты, оба анализа Codex; из полных отчётов `docs/01-research/` — разделы, на которые опираются решения ниже (ссылки вида `browser §7.2`). Там, где я расхожусь с раундом 1, это сказано прямо. Непроверенные факты помечены «⚠ проверить».

Сквозные обозначения: фазы скана **A** (до взаимодействия с баннером), **A′** (нейтральная интерактивность без клика), **B** (после «Ablehnen»), **C** (после «Alle akzeptieren»). Уровни — `critical | warning | info`. Статусы проверок — `completed | partial | inconclusive | error | skipped | not_applicable`.

## 1. Позиционирование и границы

**Одна фраза.** `dsgvo-check` — пассивный CLI-гейт для CI, который фиксирует, что немецкий сайт делает до и после «Ablehnen», сверяет это с Datenschutzerklärung и Impressum, проверяет базовую гигиену TLS/заголовков/почты и выдаёт воспроизводимые технические наблюдения в JSON со стабильными ID и `crmCode` — без правовых выводов.

**MVP = релиз.** Все 15 P0 каталога **плюс CONSENT-05**. CONSENT-05 поднимаю в релизный объём, потому что ядро идеи заказчика — «срабатывает ли кнопка Ablehnen и что меняется после отказа»; CONSENT-04 без проверки эффекта отказа эту задачу не закрывает (согласен с анализом Sol). Плюс служебные находки `SCAN-*` (бот-режим CMP, гео, блокировка, троттлинг, нераспознанный баннер) — без них P0 по консенту дают ложные падения CI.

В релиз входят: CLI одной командой, JSON по опубликованной схеме, консольная сводка, **HTML-отчёт** (самодостаточный, без JS), GitHub Action, GitLab-шаблон, Docker-образ, npm-пакет, тесты «нарушение + чисто» на каждую проверку, README.

**Сознательно не делаем в MVP** (список non-goals для брифа, чтобы объём не расползался):
- P1 кроме CONSENT-05 и P2 целиком (реализуются после релиза по каталогу; FILE-01 — см. ниже);
- PDF (отдельная команда поверх того же HTML — этап 4 как stretch, иначе первый пост-релиз);
- мобильный viewport как второй прогон (DSK Rn. 124 требует проверять блокировку и на mobile — P1 после релиза; бюджет и структура отчёта под это заложены: `viewport` — часть ключа находки);
- batch-режим «много сайтов», история прогонов, сравнение «было/стало» между аудитами (один URL на процесс; матрица CI — обёртка);
- Австрия/Швейцария (DSG/nDSG), не-немецкие сайты, TCF/GPP-анализ (кроме чтения `__tcfapi('ping')`), Pay-or-Okay как оценка, AI Act, PDF/A;
- server-side tracking (sGTM → CAPI/Measurement Protocol): из браузера не наблюдаем, в отчёте честно пишем «first-party Tracking-Endpoint erkannt; serverseitige Weiterleitung nicht feststellbar»;
- активные проверки любого рода, stealth, обход CAPTCHA/WAF/bot-блоков, подбор DKIM-селекторов за пределами фиксированного списка, словари бэкапов, попытки входа;
- внешние плагины (`--plugin`) — P2; BFSG-01/PERF-01 как плагины после релиза;
- отдельная проверка «передача за пределы ЕС» (см. ниже);
- сводная оценка/grade: только уровни по ID и `--fail-on`.

**Расхождения идеи и ТЗ — как разрешаю:**

| Расхождение | Решение |
|---|---|
| Идея: HTML/PDF; ТЗ: JSON + консоль обязательны, HTML «если успеешь», PDF нет | HTML — в релизе (это артефакт, который заказчик отдаёт клиентам аудита; при дизайне «без JS, один файл» он стоит 3–4 дня). PDF — команда `dsgvo-check report --pdf` поверх того же HTML, этап 4 stretch / первый пост-релиз. ТЗ — контракт, идея — приоритет внутри свободы ТЗ |
| Идея: «код возврата для CI (опционально)»; ТЗ: обязательные `0/1/2` | Коды обязательны и всегда выдаются. «Опциональность» реализуется режимом `--fail-on none`: отчёт строится, порог не применяется, `2` при сбое сканера остаётся |
| Идея: `.git`/`.env`/бэкапы в ядре; каталог: FILE-01 в P2 с 0 находок из 80 | FILE-01 — отдельный **opt-in** модуль `--probe-files` (по умолчанию выключен), фиксированный список путей, 4 KiB, без сохранения тела; реализуется на этапе 3 после P0+CONSENT-05, если остаётся бюджет, иначе первым после релиза. Приоритет реализации и тяжесть находки разведены: при подтверждённой сигнатуре — `critical` (T0 каталога) |
| Идея: «передача данных за пределы ЕС»; в каталоге проверки нет | Отдельной проверки нет (согласен с legal-map): пассивно устанавливается только получатель и место его регистрации, не правовой механизм передачи. Вводится атрибут находки `thirdCountrySignal` (страна юрлица получателя из нашего каталога, статус adequacy/DPF из `data/legal/adequacy.json` с датой; IP-страна только при включённом `--geoip`). На уровень не влияет. Формулировка — «Empfänger laut Dienstekatalog: Google LLC (US); Angemessenheitsstatus laut adequacy.json Stand …», никогда «Datenübermittlung in die USA» |
| ТЗ: честный UA со ссылкой на репозиторий; исходники RCB/isbot: токен `check`/URL в UA включает бот-режим CMP | Два профиля UA (раздел 3): `honest` (буквально по ТЗ) — умолчание до калибровки; `visitor` (чистый Chrome UA + идентифицирующий заголовок запроса) — документированная опция. Выбор умолчания — решение заказчика по данным калибровки (раздел 14), моя рекомендация там же |
| ТЗ: «только пассивные проверки»; TLS-04/FILE-01/ADMIN-01 требуют собственных запросов | Три класса действий (раздел 11): наблюдение публичного сайта (всегда), ограниченные технические пробы (DNS, HTTP→HTTPS, заголовки, 2 TLS-handshake — базовый профиль), пробы экспозиции (FILE-01, ADMIN-01 — opt-in). Фиксируется в ADR «Пассивный режим» |

**Ответ на каталог vs отчёты по уровням.** Каталог оперирует тирами `crmCode` (T0/T1/T3), отчёты — enum уровней. Принимаю явный маппинг как правило ruleset: **T0 → critical; T1 → critical-способный** (critical при высокой уверенности и устоявшейся правовой линии, иначе warning); **T3 → максимум warning**. Это совпадает с выводом legal-map «тех. стандарт — максимум warning» и объясняет, почему PRIV-01 (T3) по умолчанию warning, а TLS-01/02 (T1) — critical. P2 без `crmCode` получают `null` до справочника заказчика.

## 2. Архитектура

**Поток данных** (модель Lighthouse/WEC: сбор отделён от оценки, оценка отделена от текста):

```
CLI/config → Engine (план скана по needs проверок)
   → Collectors: browser (Playwright/CDP) · http (undici) · tls (node:tls + raw ClientHello) · dns (Resolver)
   → Snapshot — неизменяемый, версионированный JSON (--save-snapshot / --from-snapshot)
   → Checks — чистые функции (Snapshot, ctx) → CheckResult { status, observations[] }
   → Assess — ruleset (данные): (checkId, class, confidence) → severity, crmCode, primary/linked
   → Dedup/Link — одно наблюдение → одна primary-находка, остальные linked (раздел 5)
   → Post — suppressions/baseline → порог → exit code
   → Reporters: json · console · html · junit · gh-summary (· pdf из html отдельной командой)
```

Правила зависимостей (проверяются линтером Biome на ограничения импортов и тестом на граф): `core` не знает ни `checks`, ни `collectors`; `checks/*` импортирует только `core/api` — ни Playwright, ни `node:*` I/O; `collectors` ничего не знают о проверках и публикуют только типизированные части Snapshot; `reporters` читают готовый Report, ничего не вычисляют.

**Модули и ответственность**

| Модуль | Отвечает за | Не отвечает за |
|---|---|---|
| `core/engine` | план скана (какие collectors поднимать по `needs` выбранных проверок), бюджет времени, исполнение проверок, статусы, `summary`, exit-код | содержимое проверок, сетевой I/O |
| `core/snapshot` | схема Snapshot v1, сериализация, редактирование секретов **до** записи (значения cookies → хеш, ID-параметры URL → маска) | интерпретация |
| `core/assess` | применение ruleset-профиля (`de-2026` по умолчанию), маппинг класс → уровень, `crmCode`, `legalNote`-ссылка, dedup/link, fingerprint | тексты |
| `collectors/browser` | фазы A/A′/B/C, профиль на фазу, захват сети (события контекста + CDP), cookies/storage по фазам, DOM-факты, CMP-адаптеры (detect/state/reject/accept/verify), скриншот баннера, извлечение текста Datenschutzerklärung, CDP Audits (mixed content) | оценка |
| `collectors/http` | undici-клиент с лимитами, журнал запросов как evidence: TLS-01 цепочка, заголовки, `security.txt`, FILE-01/ADMIN-01 (opt-in), readme.txt/style.css для VULN | браузерные запросы |
| `collectors/tls` | `tls.connect` + `X509Certificate` + свой `checkHost`; TLS-04 через сырой ClientHello (план А) с fallback на `DEFAULT@SECLEVEL=0` | оценка стойкости шифров |
| `collectors/dns` | TXT/MX/A/AAAA/CAA/CNAME через инжектируемый `Resolver`; DMARC tree walk (RFC 9989); SPF-парсер с лимитом lookups; DKIM по фиксированному списку; DS/AD — opt-in | — |
| `egress` | локальный in-process forward-proxy (CONNECT + HTTP) для браузера **и** undici: резолв хоста один раз инжектируемым резолвером, запрет private/loopback/link-local/IMDS, счётчик запросов, token-bucket на хост, уважение `Retry-After` | — |
| `checks/<ID>` | одна папка на проверку: `index.ts`, `fixtures/violation.snapshot.json`, `fixtures/clean.snapshot.json`, `README.md` (генерирует `docs/checks/`) | тексты, уровни |
| `data/` | `services/*.yaml` (каталог сервисов), `cookies/{allowlist,catalog}.yaml`, `cmp/*.yaml` (семантика первого уровня), `claims/*.yaml` (PRIV-02), `ruleset/de-2026.yaml` (уровни), `messages/{de,en}.yaml` (ICU MF1), `legal/<ID>.de.md` + `legal/context.json` + `legal/adequacy.json`, `vuln/` (снапшоты KEV, retire jsrepository), `fingerprints/*.yaml` (CMS/плагины), `legal-02/*.yaml` (устаревшие нормы) | код |
| `report/*` | JSON (Ajv-валидный по схеме), консоль (санитизация ANSI/bidi), HTML (Preact SSR, CSP, без JS), JUnit, GitHub Job Summary; `report --pdf` | — |

**Интерфейс проверки** (контракт; это основа «новая проверка без правок ядра»):

```ts
export type Severity = 'critical' | 'warning' | 'info';
export type Confidence = 'high' | 'medium' | 'low';
export type CheckStatus = 'completed' | 'partial' | 'inconclusive' | 'error' | 'skipped' | 'not_applicable';
export type Phase = 'A' | 'A1' | 'B' | 'C';

export interface Observation {
  checkId: string;                 // 'CONSENT-01'
  class: string;                   // класс факта: 'analytics' | 'tag-manager' | 'fonts' | 'hsts-missing' | …
  confidence: Confidence;          // уверенность детекта, не тяжесть
  phase?: Phase;
  pages: string[];                 // где наблюдалось
  evidence: Evidence[];            // типизированные доказательства (раздел 5)
  params: Record<string, string | number | boolean>; // плейсхолдеры для messages/*.yaml
  observationId?: string;          // общий факт для нескольких ID (dedup/link)
  thirdCountrySignal?: ThirdCountrySignal;
}

export interface CheckResult {
  status: CheckStatus;
  observations: Observation[];
  reason?: string;                 // почему partial/inconclusive/not_applicable
}

export interface Check<K extends SnapshotKey = SnapshotKey> {
  id: string;                      // стабильный ID каталога
  priority: 'P0' | 'P1' | 'P2';
  module: 'browser' | 'http' | 'tls' | 'dns' | 'mixed';
  crmCode: string | null;          // null только для P2 без кода и SCAN-*
  needs: readonly K[];             // 'browser.A' | 'browser.B' | 'http.headers' | 'dns.txt' | 'policyText' | …
  fingerprintKey(o: Observation): string[];       // стабильная часть идентичности (раздел 5)
  run(snapshot: Pick<Snapshot, K>, ctx: CheckContext): CheckResult;   // чистая, без I/O
}

export interface CheckContext {
  services: ServiceCatalog;        // host → { id, company, hqCountry, category, aliases, crmCode }
  cookies: CookieCatalog;          // имя/домен → категория, allowlist
  cmp: CmpSemantics;               // данные по 7 CMP (для проверок, читающих CmpState)
  isFirstParty(host: string): boolean;   // eTLD+1 (tldts) + поддомены цели
  now: Date;                       // инжектируемое время (сроки сертификатов, suppress)
}
```

Уровень **не** задаётся в проверке: проверка возвращает `class` и `confidence`, а `data/ruleset/de-2026.yaml` говорит `CONSENT-01: { analytics: critical, ads: critical, tag-manager: warning, cdn: info, unknown: info }`. Так заказчик меняет уровни PR-ом в данные, а не в код, и уровень детерминирован: `severity = f(observation, ruleset, config)`.

**Добавление новой проверки без правок ядра:** (1) папка `src/checks/<ID>/` с `index.ts` (`defineCheck({...})`) и двумя фикстурами; (2) одна строка в `src/checks/index.ts` (явный список — это слой checks, не ядро; glob-автозагрузку и автоподключение `node_modules`-плагинов не делаем: недетерминизм и supply-chain-риск); (3) записи в `messages/de.yaml`, `messages/en.yaml`, `ruleset/de-2026.yaml`, `legal/<ID>.de.md`. **Тест полноты реестра** (L0) падает, если чего-то нет: регистрация, обе фикстуры, ключи `title/summary/remediation` в de и en, запись в ruleset для каждого `class`, который проверка объявляет, `crmCode` (или явный `null` с комментарием), `legalNote`, уникальность ID. Если новой проверке нужны новые данные Snapshot — это расширение collector'а (minor-версия Snapshot), не ядра.

**Где живут данные.** Всё в `data/` как YAML-источники, при сборке валидируются (zod) и компилируются в JSON, попадают в npm-пакет и Docker-образ. Владение: `messages/de.yaml`, `legal/*`, `ruleset/*` — CODEOWNERS заказчик (юридическая зона); `services`, `cookies`, `cmp`, `fingerprints` — разработка, заказчик ревьюит алиасы. У каждого набора — `version`, `verifiedAt`, `reviewBy`; CI предупреждает при просрочке `reviewBy`, для записей со статусом `proposed`/`guidance` — падает (принцип regulatory §10.2). Данные могут релизиться без кода (patch-релиз с бампом `rulesetVersion` CalVer `2026.10.0`). Скачиваемые наборы (KEV, retire jsrepository, EasyPrivacy-кэш при включении) обновляются командой `dsgvo-check update` и фиксируются в `report.datasets[]` с датой и SHA-256.

**Лицензионная политика данных** (из data-sources, принимаю без изменений): в репо и образе только CC0/PDDL/MIT/Apache/CC BY; CC BY-SA и GPL — только в пользовательском кэше отдельными файлами и только opt-in; NC — никогда. Каталог сервисов формируем сами из собственных аудитов заказчика и документации вендоров (§ 87a UrhG — чек-лист в PR-шаблоне).

**Режимы воспроизводимости.** `--save-snapshot dir/` сохраняет Snapshot (уже отредактированный), `--from-snapshot dir/` прогоняет проверки и отчёты без сети — это и регрессионная фикстура L1, и путь перегенерации отчёта с новыми немецкими текстами. Связь отчёт ↔ снапшот фиксируется `report.snapshotSha256`.

## 3. Жизненный цикл скана и фазы согласия

**Цель и границы скана.** Вход — один URL. Канонизация: следуем редиректам (≤ 5) HTTP-клиентом, записываем цепочку (evidence для TLS-01), финальный origin — цель; `scope` = eTLD+1 финального URL (tldts). Редирект на другой eTLD+1 — записывается, сканируется финальный, в отчёте `scan.target.input` и `scan.target.final`. Поддомены цели посещаются только если ссылка на них стоит в навигации/подвале стартовой (1 переход, без обхода). Если цель резолвится в private/loopback/link-local — отказ (exit 2) без `--allow-private` (режим фикстур и внутренних сайтов).

**Браузер и окружение.** Chromium **Chrome for Testing new headless** (`channel: 'chromium'`), не headless-shell: shell отдаёт `HeadlessChrome` в `Sec-CH-UA` даже при подменённом UA (browser §3.4, эксперимент), что включает Usercentrics/RCB/isbot. Цена — +75 МБ образа. `locale: 'de-DE'`, `timezoneId: 'Europe/Berlin'`, viewport 1440×900, без `DNT`/`Sec-GPC` (иначе RCB/Borlabs молча решают без баннера — ложное «баннера нет»), `serviceWorkers: 'allow'`, `acceptDownloads: false`, `javaScriptEnabled: true`, `chromiumSandbox: true` с режимом `--sandbox auto|require|off` (раздел 11). В отчёте — раздел `scan.environment` («Messumgebung»): чем наша среда отличается от Chrome посетителя (нет расширений/adblock, `navigator.webdriver=true`, отключённые Playwright-фичи, 3P-cookies включены, HTTP/3 отключён из-за egress-прокси, без preconnect при `newContext`). Это защита методики (§ 824 BGB) и честность перед аудитором — пробел, отмеченный критиком.

**Профиль на фазу.** Каждая фаза — свежий временный профиль `launchPersistentContext(tmpdir)` (удаляется после фазы). Аргумент browser §7.2/§10 сильнее: `newContext()` ведёт себя как Incognito (preconnect не выполняется — экспериментально), а мы измеряем «первый визит обычного посетителя». Цена: ~1–2 с на запуск, `userDataDir` в `tmpfs` при `--read-only` контейнере, тестовый CA в L2 — в профиль. Фиксируется ADR «Профиль браузера» с условием пересмотра: если замер на калибровочном корпусе не покажет разницы в находках, откат на `newContext()` + пометка «Inkognito-ähnlich» в Messumgebung. Не согласен с engineering §2.9 «newContext на каждый скан» как с окончательным решением.

**Фазы и прогоны**

| Фаза | Контекст | Действия | Даёт |
|---|---|---|---|
| **A** до взаимодействия | свежий профиль | страницы из набора (ниже) подряд, **без кликов**; на каждой — ожидание тишины; снимок cookies/storage/CMP-состояния после каждой страницы | CONSENT-01/02/03, TRACK-01, EMBED-*, LEGAL-01, TLS-03, Consent Mode default, PRIV-* (сервисы) |
| **A′** нейтральная интерактивность | тот же профиль, стартовая и Kontakt | `mouse.move`, `mouse.wheel(0,400)`, `keyboard.press('Shift')`, без кликов; окно тишины 3 с/10 с | delay-JS (WP Rocket), Borlabs «баннер после взаимодействия», lazy-embeds; находки помечены `trigger: interaction-without-consent`, уровень как в A (скролл ≠ согласие: Planet49, EDPB 05/2020 Rn. 86 ⚠ дословный текст) |
| **B** после «Ablehnen» | свежий профиль | стартовая → detect CMP → reject **первого уровня** через адаптер (или путь через «Einstellungen» с пометкой `rejectPath: second-level`) → verify → `reload` → Kontakt + 1 страница из A | CONSENT-04 (первый уровень + блокировка), CONSENT-05, Consent Mode update, LEGAL-01 без оверлея, текст Datenschutzerklärung (раскрытые аккордеоны) |
| **C** после «Alle akzeptieren» | свежий профиль | стартовая → accept → 1 страница | полный инвентарь сервисов для PRIV-01/02 и TRACK-01; контроль «отказ действительно что-то меняет» |

Последовательно A → C → B в одном профиле **не** делаем (остатки состояния исказили бы отказ). Если баннер не распознан — B выполняется как «повторный визит без клика» (для CONSENT-05 — `inconclusive`), C пропускается (`skipped`, причина `banner-not-recognized`). Если в A согласие появилось **без клика** (Cookiebot `consent.method==='implied'`, opt-out-режимы, consent-cookie CMP без взаимодействия) — отдельная находка `CONSENT-03` класса `implied-consent` и пометка всех наблюдений фазы.

**Набор страниц** (`--max-pages 6` по умолчанию; `--quick` = стартовая + Impressum + Datenschutz без C; `--thorough` до 15):
1. стартовый URL после редиректов;
2. Impressum и Datenschutzerklärung — по ссылкам со стартовой (паттерны раздела 6, LEGAL-01);
3. Kontakt/Anfahrt/Standort — место Maps и reCAPTCHA;
4. до 2 страниц «с вероятными встраиваниями»: ключевые слова ссылок навигации/подвала (`video`, `über uns`, `team`, `karriere`, `blog`, `news`, `referenzen`, `bewertungen`, `termin`, `shop`, `newsletter`) и сигналы DOM стартовой (iframe, `youtube`/`maps` в href); если ссылок мало — `robots.txt → Sitemap:`, `/sitemap.xml`, `/wp-sitemap.xml`, выбирая **разные шаблоны** (разные первые сегменты пути).

Исключаем `mailto:`, `tel:`, `#`, `javascript:`, файлы, `wp-admin`, `wp-login.php`, корзину/checkout, поиск, `logout`. `robots.txt`: стартовая и юридические страницы — всегда (это проверка одного сайта, не индексирование); дополнительные страницы — уважаем `Disallow` для `*` и нашего токена, `--ignore-robots` явно. Фиксированные пути FILE/SEC/ADMIN/VULN robots не подчиняются (он не для этого), что документируется.

**Ожидание «тишины»** вместо `networkidle` (DISCOURAGED в Playwright; long-polling и heartbeat Hotjar/чатов либо не дают наступить, либо наступает раньше таймерных тегов GTM):

```
goto(url, waitUntil='domcontentloaded', timeout=30s)
wait 'load' (≤15s, не фатально → page.loadIncomplete=true)
t0 = now
loop:  inflight = started − finished − failed   (без websocket/eventsource/media-range)
       quiet    = now − lastRequestStart ≥ 2000ms && inflight ≤ 1
       if now−t0 ≥ MIN_DWELL && quiet → break
       if now−t0 ≥ HARD_CAP → page.quietNotReached=true; break
```
A: `MIN_DWELL 6 s / HARD_CAP 20 s`; A′: 3/10; B и C: 4/12. Параметры — в конфиге, калибруются на корпусе. `page.clock` не используем (ломает сайты). Перед уходом со страницы — вторая вкладка + `bringToFront()` для `visibilitychange`-beacons (⚠ проверить, что ловит); `--netlog` как опция для доказательства preconnect/pagehide-beacons.

**Захват сети.** Подписка на `context.on('request'|'response'|'requestfinished'|'requestfailed')` **до** первой навигации (ловим `<head>`, iframes, popups, SW, dedicated workers); `page.on('websocket')`; CDP-сессия на каждую страницу/OOPIF для `initiator`, `ExtraInfo` (blockedCookies, partitionKey), `Audits.issueAdded` (mixed content, cookie issues), `DOMStorage` события. `page.route`/`context.route` для наблюдения **не** используем (отключает кэш, не видит SW) — только в тестах. Состояние запроса различаем: `attempted` (request без response), `blocked-by-browser` (CSP/mixed content), `completed`, `failed`. Запись на запрос: `phase, pageUrl, frameUrl|sw, url (с маскированными ID-параметрами), method, resourceType, cdpType, initiator, party (first|first-subdomain|third|first-party-proxy), registrableDomain, status, connectedIp (из egress-прокси), tStart относительно навигации, setCookieNames[], consentSignals {gcs, gcd, npa, dma}, fromServiceWorker`.

**Бюджет времени.** A ≈ 6 стр. × 10–20 с ≈ 1–2 мин; A′ ≈ 20 с; B ≈ 40 с; C ≈ 25 с; HTTP/DNS/TLS — параллельно браузеру. Итого ≈ 2.5–4 мин; глобальный `--timeout 8m` (при превышении — частичный JSON, статусы `partial`, exit 2 с `SCAN-TIMEOUT`); рекомендация `timeout-minutes: 15` для джобы.

**Вежливость и rate limiting** (одна таблица, фиксируется в ADR «Пассивный режим»): навигации строго последовательно, пауза ≥ 1.5 с (`--delay`); HTTP-пробы ≤ 2 req/s на хост, конкурентность 2; DNS ≤ 8 параллельно; на `429`/`503` уважаем `Retry-After`, 3 подряд → стоп модуля и `SCAN-THROTTLED` (warning); один повтор только на сетевые ошибки, FILE-01 без повторов; бюджет запросов за скан ≈ 120 HTTP + ≤ 50 DNS + 3 TLS-сокета + браузерные навигации — счётчик `scan.requestsIssued` в отчёте («Anzahl Anfragen» — прозрачность для владельца сайта). Все запросы браузера и Node идут через локальный egress-прокси (раздел 11), поэтому лимиты применяются и к браузерному трафику, а не только к HTTP-модулю (замечание Sol).

**User-Agent.** Требование ТЗ и исходники CMP конфликтуют (browser §3.2/3.4: `check\b`, `http`, `.com\b` → isbot и Real Cookie Banner считают ботом; RCB по умолчанию `accept-all-for-bots=true` → ложные CONSENT-01/02/03 именно на «честном» UA). Решение:
- HTTP-пробы без браузера: `dsgvo-check/<ver> (+https://github.com/<org>/dsgvo-check; passive DSGVO/security check)` — буквально по ТЗ; эти запросы и выглядят как сканер.
- Браузер, профиль `honest` (**умолчание до калибровки**): реальный UA Chrome с версией движка из `browser.version()` + ` dsgvo-check/<ver> (+https://github.com/<org>/dsgvo-check)`, без `HeadlessChrome`. Client Hints не трогаем (подмена brands — маскировка).
- Браузер, профиль `visitor`: немодифицированный UA Chrome; идентификация — заголовок `X-Dsgvo-Check: <ver> (+https://github.com/<org>/dsgvo-check)` на всех запросах (виден владельцу сайта в логах, не виден JS CMP) и опционально `From: <email>` по `--contact`. Это честная идентификация, но не «честный UA» в буквальном смысле ТЗ — потому решение об умолчании за заказчиком (раздел 14).
- **Рантайм-детектор бот-режима обязателен при любом профиле:** Cookiebot `isSpider()`/`isOutOfRegion`; Complianz `region==='eu'` при `cmplz_has_consent('marketing')===true` без consent-cookie; RCB/Borlabs consent-cookie с полным согласием без нашего клика; общий признак — consent-cookie любой CMP в A без взаимодействия. Срабатывание → `SCAN-BOTMODE` (warning), все CONSENT-0x фазы A понижаются до `info` с `confidence: low` и текстом «CMP hat Bot-Modus aktiviert; Prüfung eingeschränkt. Option `--ua-profile visitor` siehe README».

**Гео.** Раннеры GitHub (⚠ данные 2021) и GitLab (`us-east1` ✔) — вне ЕС; Cookiebot/Usercentrics/Complianz/Borlabs вне ЕС баннер не показывают или показывают другой (browser §4.2). Решение: (1) всегда читаем гео-сигналы CMP: `CookieConsent=-1`, `Cookiebot.isOutOfRegion`, `__ucCmp.isConsentRequired()===false`, `complianz.region`/`body.cmplz-us|cmplz-other`, Borlabs `dialogGeoIpActive` + REST `visible:false`, `__tcfapi ping → gdprApplies===false`, Consent Mode `region` без `DE`; (2) «нет баннера» + гео-сигнал → `SCAN-GEO` (warning) вместо CONSENT-03/04, CONSENT-* фазы A → `info`/`low`; (3) `--proxy` (HTTP/SOCKS5 с ЕС-выходом; учётка в CI-секрете) и README-рекомендация self-hosted раннера в ЕС для доказательных прогонов; (4) `--assume-region eu` — подсказка для отчёта; (5) `?uc_cmp_country=DE` **не** в MVP (недокументировано, меняет URL); (6) внешний сервис «узнай мою страну» по умолчанию не вызываем (лишняя передача данных третьему лицу), `--geo-check-url` по выбору пользователя. В JSON всегда `scan.egress {proxy, assumedRegion, geoSignals[]}`. Строгий режим `--require-eu-egress` — exit 2, если ни прокси, ни `--assume-region eu` (для заказчика, которому нужны доказательные прогоны).

**Блокировка/челлендж.** 403/5xx/страница-челлендж (Cloudflare/WAF) на стартовой → `SCAN-BLOCKED`, exit 2 (скан невозможен, выводов о CONSENT нет); на дополнительной странице — warning и страница исключается из знаменателя LEGAL-01. Stealth не применяем.

## 4. Баннеры и CMP

**Контракт адаптера** (один на CMP, данные селекторов — в `data/cmp/<id>.yaml`, код — минимальная логика):

```ts
interface CmpAdapter {
  id: 'borlabs' | 'cookiebot' | 'complianz' | 'usercentrics' | 'ccm19' | 'real-cookie-banner' | 'cookiehub';
  detect(page): Promise<{ present: boolean; version?: string; confidence: Confidence; signals: string[] }>;
  state(page): Promise<CmpState>;             // только чтение: JS-API / consent-cookie / TCF ping
  geoSignals(page): Promise<GeoSignal[]>;  botSignals(page): Promise<BotSignal[]>;
  firstLayer(page): Promise<FirstLayer>;      // контейнер, кнопки {role, accessibleName, kind, box, visible, contrast, element}, blocking
  reject(page): Promise<ClickResult>;         // реальный locator.click() без force по первому уровню; fallback через settings помечается
  accept(page): Promise<ClickResult>;
  verifyRejected(page): Promise<{ uiClosed: boolean; stateDenied: boolean | null; cookieDenied: boolean | null; persistedAfterReload: boolean }>;
}
```

Правила: JS-API CMP — **только чтение** (в C допустимо как fallback для accept); клик только через `locator.click()` без `force` — actionability-проверки Playwright и есть «кнопка доступна человеку»: если её перекрывает элемент — это evidence для CONSENT-04, а не повод кликнуть JS-ом. Селекторы — только CSS и role-локаторы (XPath не пробивает shadow DOM; правила autoconsent для RCB с XPath переписываем). Closed shadow DOM — чтение через CDP `DOM.getDocument({pierce:true})` ⚠ для закрытых; кликнуть законно нельзя → `info: Banner nicht vollständig auswertbar`. Iframe-CMP (Sourcepoint, consentmanager) — `frameLocator`; в семёрке их нет, но детект есть.

**Распознавание 7 CMP** — порядок реализации по каталогу (Borlabs v3 и v2, Cookiebot, Complianz, Usercentrics v3 и v2, CCM19, Real Cookie Banner, CookieHub). Детект — по двум независимым признакам из трёх (глобальный объект / скрипт / DOM-сигнатура) → `confidence: high`; один признак → `medium` (адаптер работает, но CONSENT-04 даёт только warning). Селекторы первого уровня и чтение состояния — из таблицы browser §5.2 (источники: правила `@duckduckgo/autoconsent@17.x` и исходники вендоров); всё с ⚠ проверяется на калибровочном корпусе. Особые режимы, которые адаптер обязан учитывать: Borlabs `dialogShowDialogAfterUserInteraction` (баннер только после A′) и `dialogHideDialogOnPages` (на Impressum/Datenschutz баннера нет — норма, не CONSENT-03); Cookiebot `data-level=implied`/`optout` (согласие без клика → CONSENT-03 класса `implied-consent`); CCM19 поздняя инъекция (ждать до HARD_CAP); RCB обфусцированные id — только структурные селекторы; CookieHub без гарантированной кнопки отказа на первом уровне (это как раз кейс CONSENT-04); Usercentrics v3 — shadow DOM.

**`@duckduckgo/autoconsent` (MPL-2.0)** — зависимость без модификации (файловый copyleft; юр. подтверждение заказчика ⚠) в трёх ролях: (1) резервный детектор CMP за пределами семёрки (отдаёт имя CMP для отчёта, вердикта не даёт); (2) чистая функция классификации текста кнопок (`classifyButtonTextRegex`, немецкие паттерны); (3) справочник селекторов. **Не** используем его `optOut` (идёт через API `Cookiebot.withdraw()`, через второй уровень или cosmetic), `prehide`/`enableCosmeticRules` отключены (прятать баннер CSS-ом = прятать улики). Версию пиним; правила — данные, ревьюятся. Здесь расхожусь с prior-art («detect и opt-out через autoconsent»): вердикты CONSENT-04/05 — только из наших адаптеров.

**Обобщённая эвристика для неизвестных баннеров** (кандидаты: видимые `role=dialog|alertdialog`, `aria-modal`, `<dialog open>`, `position:fixed|sticky` с z-index выше контента, покрытие ≥ 15 % вьюпорта или полоса у края; текст с ≥ 2 consent-ключевыми словами; кнопки классифицируются на `reject | accept | settings | save | close-ambiguous | unknown` по accessible name) даёт **только** `SCAN-BANNER-UNKNOWN` (`info`, текст «Banner nicht erkannt») со структурным evidence: скриншот области, тексты и классы кнопок, блокирует ли. Порог уверенности эвристики (`score ≥ 0.8`) влияет лишь на то, пишем ли «Banner erkannt (heuristisch), Ablehnen-Schaltfläche auf erster Ebene nicht gefunden — manuell prüfen» вместо «Banner nicht erkannt». CONSENT-04 от эвристики **не** выдаётся ни на каком уровне — это буква ТЗ; расхожусь с browser §5.4, допускающим CONSENT-04 `heuristic` при score ≥ 0.8. Если ни адаптер, ни эвристика ничего не нашли, а сторонние сервисы, требующие согласия, есть — CONSENT-03 (при отсутствии гео/бот-сигналов).

**Правило «не распознал → info»**: находка `SCAN-BANNER-UNKNOWN` (info, `crmCode: null`), CONSENT-04 и CONSENT-05 получают статус `inconclusive` с причиной; CONSENT-01/02/03 фазы A сохраняют уровни (они не зависят от распознавания). В консоли и HTML — дословно «Banner nicht erkannt». Отдельный ID вместо info под `CONSENT-04` выбран, чтобы в CRM под `T1_CONSENT_BANNER_BROKEN` не попадал шум; альтернатива — вопрос заказчику.

**CONSENT-04 — что измеряем и что решаем.** Адаптер отдаёт первый уровень: список кнопок с accessible name, классом, геометрией, контрастом, типом элемента (button/link), признак блокировки (overlay/`aria-modal`/`inert`/scroll-lock/`elementFromPoint` над контентом). Решение по ruleset: распознанная CMP (`high`) + блокирующий баннер + на первом уровне есть `accept`, но нет `reject` (reject только в `settings`, или вместо него `close-ambiguous` вроде «Verbergen», «×», «Später») → класс `blocking-no-first-level-reject` → **critical**; то же при неблокирующем баннере → класс `non-blocking-no-first-level-reject` → **warning** (DSK Rn. 124–125 — спорная зона, OLG Köln 6 U 80/23 ⚠ Rechtskraft); «×»/«Schließen» ведёт к согласию (после клика состояние = accepted) → как blocking; Pay-or-Okay (обнаружены ключевые слова `Abo`, `werbefrei`, цена) → класс `pay-or-okay` → **info** + ручная проверка; «равноценность» (площадь, контраст, тип элемента) — только метрики в evidence, без вывода («Dark Pattern» и «manipulativ» в стоп-списке). Расхожусь с regulatory (warning для блокирующего): правовая линия для блокирующего баннера устоялась (VG Hannover, OLG Köln, DSK, EDPB TF Type A), а каталог ведёт CONSENT-04 как P0/T1 — critical обоснован; окончательный уровень подписывает заказчик.

**Проверка, что отказ сработал** (B): три независимых факта + устойчивость: (1) UI первого уровня закрыт (`firstLayer().container` не видим); (2) состояние CMP или consent-cookie = отказ (`Cookiebot.consent.*===false`, `borlabs-cookie.consents` только essential, `cmplz_*` без marketing/statistics, `__ucCmp.getConsentDetails()`…); (3) после `reload` и перехода на следующую страницу нет запросов классов analytics/ads и новых не-allowlisted cookies; (4) consent-cookie пережила reload. Если (1) не выполнено — `ClickResult.failed` → CONSENT-04 класса `reject-ineffective` (critical, если CMP `high`) и B для CONSENT-05 `inconclusive`; если (1)+(2) выполнены, а (3) нет — это CONSENT-05 (раздел 6); если отказ прошёл только вторым уровнем — `rejectPath: second-level` в evidence CONSENT-04, B выполняется (CONSENT-05 измерим).

**Повторный показ** после отказа на второй странице — фиксируем как атрибут (`bannerReshownAfterReject`), отдельный ID (CONSENT-07 у regulatory) не вводим в MVP.

**Evidence-типы** (открытое перечисление, новые — minor): `request` (URL с маскировкой, метод, тип, инициатор, статус, IP, тайминг, состояние), `cookie` (имя, домен, путь, срок, флаги, partitionKey, `setBy: set-cookie|script`, `valueSha256` первые 12 hex — значение **никогда**), `storage` (`localStorage|sessionStorage|indexedDB`, origin, ключ, хеш значения), `header` (URL, имя, значение или `absent`), `dns` (qname, qtype, rcode, ответ, резолвер, время), `tls` (хост, IP, SNI, протокол, issuer, SAN, даты, fingerprint, ошибка валидации, trust store), `dom` (селектор/роль, accessible name, геометрия, видимость, `href`), `screenshot` (data: JPEG области баннера, ≤ 200 КБ), `file` (путь, статус, content-type, прочитано байт, сигнатура — без тела), `text` (цитата ≤ 300 символов, URL, смещение), `consentSignal` (`gcs`/`gcd`/`dataLayer`-команда с region и временем). Каждое evidence несёт `source` (набор данных + версия), если классификация опиралась на данные.

**Fingerprint для baseline:** `fingerprint = "sha256:" + hex(sha256(JCS({ v: 1, checkId, scope, key })))` (JCS — RFC 8785), `scope` = eTLD+1 цели (+ origin, если сканируется поддомен), `key` = `fingerprintKey(observation)` проверки: EMBED-01 → eTLD+1 стороннего хоста; CONSENT-01 → `[class, eTLD+1 хоста]`; CONSENT-02 → `[cookieName, cookieDomain]`; HDR-01 → имя заголовка; MAIL-* → почтовый домен; LEGAL-01 → тип документа; VULN-* → `[component, cveId]`; CONSENT-04 → `[cmpId, class, viewport]`. Не входят: query-строки, значения, время, URL страницы для находок уровня сайта, текст. Версия алгоритма `v` — в хеше, миграция baseline документируется. Suppress-файл `.dsgvo-check/suppressions.yaml`: записи по `id` или `fingerprint` с обязательными `reason`, `expires`, опционально `owner`; просроченная запись снова считается и даёт warning; подавленные находки остаются в отчёте с `suppressed: {reason, expires}` и отдельным счётчиком. `dsgvo-check baseline create` → `--baseline file` учитывает в пороге только новые fingerprint'ы. Baseline никогда не подавляет `checkErrors` и неполное покрытие.

**Уровни и уверенность — разные оси.** `severity` — закрытый enum `critical|warning|info` (новое значение = major). `confidence` — `high|medium|low` — уверенность детекта (сигнатура известного сервиса = high; эвристика/одиночный признак = medium; понижение SCAN-BOTMODE/SCAN-GEO = low). **Порог учитывает только primary-находки с `confidence ≥ minConfidence`** (`--min-confidence high` по умолчанию; `medium` — опция). Так недетерминизм (A/B-тесты, ротация рекламы) и неполная наблюдаемость не роняют CI молча — замечание критика о политике уверенности.

**Один факт → одна primary-находка** (матрица дедупликации; остальные ID по тому же `observationId` — `primary: false`, `role: inventory|linked`, в `summary.primary` не считаются, порог не роняют):

**Точная семантика `--fail-on` и кодов выхода**

`--fail-on critical` (умолчание): порог превышен, если есть ≥ 1 неподавленная primary-находка `critical` с `confidence ≥ minConfidence`. `--fail-on warning`: то же для `warning` или `critical`. `--fail-on none`: порог не применяется. `info` никогда не роняет. Порог не связан с P0/P1/P2 и с `crmCode`.

| Ситуация | Код | JSON |
|---|---|---|
| Скан завершён (фазы A и B выполнены или помечены причиной), порог не превышен | `0` | `summary.exitCode: 0` |
| Порог превышен | `1` | находки в отчёте |
| Неверные аргументы/конфиг/URL; браузер не установлен или не стартовал; внутренняя ошибка; unhandled rejection | `2` | по возможности частичный JSON с `scan.fatal {code, message}` |
| Стартовый URL недоступен (DNS, соединение, таймаут навигации) | `2` | `SCAN-UNREACHABLE`; DNS/TLS-модули всё равно отрабатывают и пишут находки (MAIL-*, TLS-02) |
| Стартовая отдаёт 403/5xx/челлендж (WAF, CAPTCHA) | `2` | `SCAN-BLOCKED`; выводов о CONSENT нет |
| Глобальный таймаут `--timeout` | `2` | `SCAN-TIMEOUT`, статусы `partial`, собранные находки сохраняются |
| Сертификат цели невалиден → Chromium блокирует сайт | `1` (если `critical ≥ fail-on`) | TLS-02 `critical`; браузерные проверки `skipped` с причиной `tls-error`; `--insecure` продолжает фазы с `ignoreHTTPSErrors` и пометкой в Messumgebung |
| `http://` без https вообще | по порогу | TLS-01 `critical`; скан продолжается по http |
| Упала **одна** проверка (DNS timeout, исключение в `run`) | **по порогу `0/1`**, не `2` | `checks[].status: error`, `summary.checkErrors`; `--strict` → `2` («никогда не зелёный, если не всё проверено» — как opt-in) |
| Баннер не распознан | по порогу | `SCAN-BANNER-UNKNOWN` info; CONSENT-04/05 `inconclusive`; CONSENT-01/02/03 как есть |
| Фаза B не выполнена (отказ не кликнулся) | по порогу | CONSENT-04 `reject-ineffective`; CONSENT-05 `inconclusive` |
| Бот-режим/гео-сигнал | по порогу | SCAN-BOTMODE/SCAN-GEO warning; CONSENT-* фазы A → info/low (порог не роняют) |
| Троттлинг 429 ×3 | по порогу | SCAN-THROTTLED warning; затронутые проверки `partial` |
| Порог превышен **и** фатальная ошибка | `2` | находки сохраняются; CI видит неполный скан (приоритет фатального — согласен с Terra только для фатальных случаев) |
| Порог превышен и упала одна проверка | `1` | — |

Расхожусь с engineering §3.7 (`2` при любой ошибке проверки): таймаут одного DKIM-запроса не должен сигнализировать «сканер упал» — это ломает семантику ТЗ и доверие к коду `2`. Компромисс — `--strict`. Конфигурация через `.dsgvo-check.yaml` (zod-схема `config.v1.json`) и флаги; флаги важнее.

**Стабильность контракта.** ID каталога — публичный контракт, не переиспользуются; разделение проверки → новый ID + `deprecated/replacedBy`. Minor: новое необязательное поле, новый ID, новый `evidence.type`, новый `class`, новый `phase`. Major: удаление/переименование, новое значение закрытого enum (`severity`, `status`), смена семантики exit-кода/порога/fingerprint. Смена маппинга `crmCode` — minor с записью в CHANGELOG (вопрос заказчику: переживёт ли импорт CRM). Потребители обязаны игнорировать неизвестные поля и трактовать неизвестные enum-значения как unknown — записано в README схемы. Отчёты-образцы прошлых minor-версий лежат в `schemas/examples/` и проверяются текущей схемой.

## 8. Отчёты

**JSON** — контракт (раздел 5). Всегда содержит `messageId` + `params` для машин и отрендеренные `title/summary/remediation` на `--lang` для людей; `legalNote` — ссылка на статический текст по `checkId` (сам текст в HTML, в JSON — `ref` + статус), `legalContext` и `ruleset.rechtsstand`. Пишется всегда, даже при exit 2 (частичный). `report.json` валидируется Ajv перед записью.

**Консоль** — сводка: цель, Rechtsstand/ruleset, покрытие (страницы, фазы, CMP, «Banner nicht erkannt» если так), таблица primary-находок по уровню (ID, уровень, уверенность, краткий текст, число evidence), linked/suppressed/checkErrors счётчиками, служебные `SCAN-*` блоком «Einschränkungen der Messung», exit-код и причина. Все строки с сайта проходят санитизацию (C0/C1 кроме `\t`, bidi-override U+202A–202E/U+2066–2069), длина `summary` ограничена; `--format console` по умолчанию, `--quiet`, `--no-color`.

**HTML** — один самодостаточный файл **без JavaScript** (интерактивность через `<details>`/якоря): `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'sha256-…'; img-src data:; base-uri 'none'; form-action 'none'">`, `<meta name="referrer" content="no-referrer">`; системный стек шрифтов (в Docker — Noto/DejaVu для умлаутов), inline-SVG иконки, скриншоты баннера как `data:` JPEG ≤ 200 КБ; шаблонизатор Preact 11 + `preact-render-to-string` с экранированием по умолчанию, `dangerouslySetInnerHTML` запрещён правилом Biome; URL с сайтов — **текстом** (клик по трекерному URL из отчёта = визит к трекеру), не ссылками. Структура: шапка (цель, дата UTC, версия тула, ruleset/Rechtsstand, Messumgebung, egress), дисклеймер, «Einschränkungen der Messung» (SCAN-*), сводка по уровням, находки по ID с evidence-таблицами и `legalNote` («Rechtlicher Kontext (Stand …)» — статический текст, вычитанный заказчиком), покрытие (страницы, фазы, запросы), `datasets`, атрибуции. Тест (L2): открыть в Chromium с `route('**', abort)` → ноль сетевых запросов, ноль CSP-нарушений, ни одной ссылки со схемой не http(s).

**PDF** — отдельная команда `dsgvo-check report --from report.json --pdf out.pdf` (не в скан-процессе: отчёт перегенерируем с исправленными текстами заказчика): `page.setContent(html)` в контексте с `javaScriptEnabled: false` и `route('**', abort)`, `page.pdf({ format: 'A4', printBackground: true, tagged: true, outline: true, displayHeaderFooter: true })`; PDF/A — вне scope. Этап 4 stretch.

**JUnit XML** (P1 для GitLab MR-виджета: проверка = testcase, primary-находка ≥ warning = failure; XML-построитель с очисткой недопустимых символов) и **GitHub Job Summary** (Markdown, экранирование, без картинок, SHA-256 `report.json` для целостности) — этап 2.

**Язык.** `--lang de` по умолчанию (аудитория), `en` — второй; тексты в `data/messages/{de,en}.yaml` в ICU MessageFormat 1 (`intl-messageformat`, BSD-3), без Markdown (абзацы + отдельное поле `links[]`), ключи `<ID>.title|summary|description|remediation`, `report.disclaimer`, `report.bannerNotRecognized`, `scan.*`. L0-тесты: паритет ключей и плейсхолдеров de/en, парсинг ICU, **стоп-слова для `de`** (список legal-map §3.2: `verstößt`, `rechtswidrig`, `unzulässig`, `ohne Einwilligung`, `Tracker` как метка, `Datenübermittlung in die USA`, `Datenleck`, `Abmahngefahr`, `konform`, `bestanden`, `manipulativ`, `Dark Pattern` …) с явным allowlist-исключением. До этапа 3 — черновые немецкие тексты из legal-map §2.2/2.4/2.6 с пометкой `draft: true` (отчёт печатает «Textentwurf — Prüfung durch Auftraggeber ausstehend»), заказчик заменяет PR-ом в `de.yaml`.

**Дисклеймер** — черновик legal-map §3.3 (тип отчёта, автоматизация, UTC, сеть/ASN выхода, UA, версии баз, «keine Aussage über Rechtmäßigkeit», «Fehlen einer Beobachtung ≠ Beanstandungsfreiheit», «ersetzt keine Rechtsberatung», Apache-2.0 §§ 7–8) + абзац о Messumgebung; заказчик вычитывает к этапу 3. Абзац «Werte von Cookies … werden nicht gespeichert» верен всегда, потому что флага `--include-cookie-values` **нет** (убираю предложение engineering §6.8 — минимизация данных и честный дисклеймер важнее).

**Что редактируется до сериализации (единый модуль `redact` в `core/snapshot`):** значения cookies → `valueSha256` (12 hex) + длина; ID-параметры URL (`cid`, `_gid`, `uid`, `fbp`, `sid`, `gclid`, `fbclid`, `email`, `token` и allowlist-инверсия: оставляем только `tid`, `id`, `v`, `en`, `gcs`, `gcd`, `dma`, `npa`) → `<redacted>`; `Authorization`/`Cookie`/`Set-Cookie`-значения в заголовках; тела FILE-01 — никогда (только «Signatur passt»); POST-тела — только наличие и размер (+ распознанные consent-параметры); TC-String → хеш; скриншоты — только область баннера; список пользователей ADMIN-01 — только количество. `--full-urls` отсутствует в MVP (вопрос заказчику о достаточности доказательств). HAR (`--har`, `content: 'omit'`, с предупреждением) — отдельный чувствительный артефакт, выключен по умолчанию.

## 9. Тестирование

**Требование ТЗ «для каждой проверки фикстура с нарушением и чистая»** выполняется на двух уровнях и контролируется тестом полноты реестра:
- **L1 (обязательно для каждого ID):** `src/checks/<ID>/fixtures/violation.snapshot.json` и `clean.snapshot.json` — записанные Snapshot-фрагменты; тест: `violation` → ≥ 1 observation ожидаемого `class` и после assess — ожидаемый уровень/`crmCode`/fingerprint; `clean` → 0 observations и статус `completed`; дополнительно для рискованных ID (CONSENT-0x, PRIV-*, VULN, MAIL-03, TLS-04) — `inconclusive.snapshot.json` (неполные данные → статус, а не `pass`) и пограничные случаи (negated mention, implied consent, tag-manager без тегов, `~all` + DMARC reject). Без браузера, < 30 с.
- **L2 (для каждой проверки с browser/http/tls/dns источником):** фикстур-сайт `violation` и `clean`, который прогоняется **настоящим сканером** в Chromium без интернета; результат сравнивается golden-снапшотом (`toMatchFileSnapshot`, нормализация времени/портов/версий, сортировка по fingerprint) и Ajv-валидируется.

**Юнит на записанных артефактах vs интеграция с браузером.** Проверки — чистые функции → L1 покрывает алгоритм детекта и ruleset; L2 покрывает collectors (захват сети до навигации, cookies по фазам, CMP-адаптеры, извлечение текста ДСЭ, CDP Audits) и связку. Разделение даёт быстрые PR-тесты и честную проверку «ранний запрос в `<head>` пойман» (Terra №2) там, где он возникает.

**Сеть без интернета (L2):** все L2 — в Docker `--network none` (гарантия, а не дисциплина). Один **egress-прокси** (тот же, что в проде) получает инжектированный резолвер с картой `host → fixture` (`site.test`, `tracker.test`, `fonts.test`, `cmp.test`, `mail.test`…); Chromium и undici ходят через него → одна карта хостов для браузера и Node, без `/etc/hosts` и без `--host-resolver-rules` (остаётся как запасной путь; ⚠ `MAP host ip:port` в Chromium вероятно поддерживается — `mapped_host_resolver`, проверить). Мульти-хост fixture-server (приватный пакет) различает `Host`/SNI, отдаёт страницы, iframes, shadow DOM, редиректы, SPA, `Set-Cookie`, управляемые задержки (меньше окна тишины; long-polling запрещён); любой хост вне карты → 599 и падение теста. **TLS:** тестовый CA (`@peculiar/x509`, MIT) выпускает листовые сертификаты по SNI: valid, expired, wrong-name, self-signed, неполная цепочка; CA добавляется в профиль браузера (NSS DB в `userDataDir` — persistent-профиль это упрощает) и в `ca` undici/`tls.connect`; `ignoreHTTPSErrors` — только в тестах, не касающихся TLS. TLS-1.0-сервер для TLS-04: Node `tls.createServer` с `DEFAULT@SECLEVEL=0` + `minVersion: 'TLSv1'` (⚠ подтверждено локально на Homebrew OpenSSL 3.6; на официальных сборках Node 24/26 проверить) и, независимо, записанные байты ServerHello/Alert для юнит-тестов парсера ClientHello-пробы; обязательный тест «клиент способен предложить TLS 1.0». **DNS:** инжектируемый `Resolver` + `dns2` (⚠ лицензия MIT проверить) авторитативный fake: TXT/MX/A/AAAA/CAA/CNAME, `NXDOMAIN`/`NODATA`/`SERVFAIL`/timeout, DMARC tree walk, SPF с > 10 lookups, DKIM известный/неизвестный селектор, DNSSEC `secure/insecure/bogus` — если DNS-01 реализуется. **Время:** инжектируемое `now`, `TZ=Europe/Berlin`, `LANG=de_DE.UTF-8`.

**Имитация CMP:** код реальных CMP в репозиторий не копируем (проприетарные/GPL). Для каждой из 7 — собственный минимальный симулятор контракта: DOM с опознавательными ID/классами и глобалами (`BorlabsCookie`, `Cookiebot`, `complianz`, `__ucCmp`, `consentApi`, `cookiehub`, `#ccm-widget`), конечный автомат: показать первый уровень → по «Ablehnen» писать consent-cookie «отказ» и не грузить трекеры, по «Akzeptieren» грузить; варианты: (а) равноценный отказ на первом уровне → чисто; (б) только «Zustimmen» + «Einstellungen» → CONSENT-04; (в) «Verbergen»/«×» ведёт к согласию → CONSENT-04 `close-equals-accept`; (г) кнопка отказа есть, но после клика трекеры продолжают → CONSENT-05; (д) отказ через второй уровень → `rejectPath: second-level`; (е) неизвестный баннер → `SCAN-BANNER-UNKNOWN` info; (ж) бот-режим (consent-cookie без клика) → SCAN-BOTMODE; (з) гео-сигнал → SCAN-GEO; shadow DOM и iframe-варианты там, где применимо. Это проверяет адаптер, не совместимость с реальной версией CMP — её закрывает калибровочный корпус и канарейка.

**Калибровочный корпус до этапа 3** (пробел, отмеченный критиком): заказчик даёт 10 сайтов «к этапу 3», а UA/тишина/профиль/CMP-селекторы нужны раньше. Решение: (1) запросить у заказчика 3–5 собственных или мандатных сайтов уже на этапе 1; (2) поднять **свои** тестовые инсталляции WP (один VPS, поддомены) с реальными CMP: Complianz free, RCB free, Borlabs (лицензия ~40 €), CCM19 free tier, Cookiebot free (≤ 50 страниц), CookieHub free, Usercentrics trial (⚠ условия trial) — ~3 PD; на них же A/B UA-профилей и замер persistent vs newContext. Инсталляции живут на `*.test`-подобных поддоменах реального домена, в репозиторий попадают только `expectations/*.yaml`.

**Канарейка (L4):** приватный репозиторий `dsgvo-check-canary` (отчёты о названных компаниях в публичных логах — Prangerwirkung), ночной cron: 10 сайтов заказчика (с письменным согласием владельцев — пункт раздела 14) + свои инсталляции; `expectations/<site>.yaml` с `mustFind[]`/`mustNotFind[]` по ID (размечает заказчик); сравнение образа `edge` и текущего релиза; таблица precision/recall по ID; **целевые пороги приёмки для релиза**: P0 по консенту precision ≥ 0.95 на размеченном корпусе, recall ≥ 0.9; дрейф → issue, не автоматический провал; `unreachable` ≠ регрессия; один проход на сайт за ночь, честный UA.

**Борьба с флейками:** никакого интернета в PR-тестах; никаких `waitForTimeout` (фикстуры шлют трекеры сразу или с известной задержкой < окна); динамические порты кроме 80/443 внутри netns; свежий профиль на тест, `pool: 'forks'`, `maxWorkers: 2`; ретраев в L1/L2 нет — флейк = баг; ночью L2 с `--sequence.shuffle` ×3; Chromium привязан к версии Playwright (Renovate-PR с полным L2/L3); `no-floating-promises` (oxlint-tsgolint); золотые снапшоты нормализованы. Раннер — Vitest 5 с `projects` unit/integration; `@playwright/test` не нужен (тесты гоняют наш сканер, он — браузер).

**L0/L3:** L0 — `tsc`, Biome, валидность `data/*.yaml` (zod), полнота реестра и сообщений, стоп-слова, drift схемы, актуальность `docs/checks/`; L3 — e2e: CLI в собранном Docker-образе против fixture-сети (`--allow-private`), exit-коды 0/1/2 на трёх сценариях, Action `uses: ./` на самом себе, JUnit/HTML артефакты, валидность HTML-отчёта (ноль сети/CSP).

Монорепо: один публикуемый пакет `dsgvo-check` + приватные `fixture-server`, `test-utils`; `action.yml` в корне (требование Marketplace).

Outputs: `exit-code`, `report-path`, `summary-json` (счётчики). ## 11. Безопасность и этика самого сканера

**Граница пассивности — три класса действий** (ADR «Пассивный режим»; определение: ограниченный неразрушающий аудит без эксплуатации и обхода ограничений):

| Класс | Действия | Политика |
|---|---|---|
| Наблюдение публичного сайта | навигации по ≤ 6 страницам, загрузка обычных ресурсов, один клик по кнопке баннера (reject/accept), скролл без кликов, чтение DOM/JS-API CMP | всегда; последовательно, пауза ≥ 1.5 с; `robots.txt` для дополнительных страниц |
| Ограниченные технические пробы | DNS (≤ 50 запросов, DKIM ≤ 25 селекторов из фиксированного списка), HTTP→HTTPS (≤ 8), заголовки (3), `security.txt` (2), `readme.txt`/`style.css` для VULN (≤ 25), **2 TLS-handshake** с устаревшими версиями без завершения обмена ключами (TLS-04) | базовый профиль, ≤ 2 req/s, документирован в README и в отчёте («Anzahl Anfragen») |
| Пробы экспозиции | FILE-01 (≤ 30 фиксированных путей, 1 GET каждый, 4 KiB, без повторов/рекурсии, тело не сохраняется, секреты не используются), ADMIN-01 (3 GET, без входа и XML-RPC-вызовов) | **opt-in** (`--probe-files`, `--probe-admin`), предупреждение в README: флаг не создаёт разрешения владельца сайта; рекомендуется только для собственных/мандатных сайтов |

Запрещено навсегда (документируется как non-features, чтобы не стать § 202c-инструментом): словари путей/бэкапов, подбор селекторов вне списка, попытки входа, XML-RPC-вызовы, инъекции/fuzzing, реконструкция `.git`, использование найденных учётных данных, обход CAPTCHA/WAF/bot-блоков, stealth-подмена `navigator.webdriver`/brands, автоматическая отправка претензий/жалоб владельцам, генератор Abmahnung, публичный рейтинг «нарушителей». Правовая рамка: § 202a StGB (нет Überwindung при открытой отдаче, но Modern Solution — BVerfG 15.09.2025 — делает чтение *содержимого* серой зоной → сигнатура первых байт, тело не сохраняется), § 303b (rate limit), BGH Screen Scraping I ZR 224/12 (не обходить защиту, не мешать работе), § 824 BGB/§ 4 Nr. 2 UWG (только проверяемые факты с методикой).

**Служебные файлы:** FILE-01 — только путь, статус, content-type, прочитанные байты, имя сигнатуры, сравнение с базлайном; лог без тела; при совпадении — немедленное закрытие соединения (`destroy` после 4 KiB); `.git/HEAD` не влечёт запросов к объектам.

**Изоляция браузера.** `chromiumSandbox: true` по умолчанию; режим `--sandbox auto` (fallback на `--no-sandbox` с предупреждением в логе и `SCAN-SANDBOX-OFF` в отчёте) и `--sandbox require` (fail-closed, exit 2) для строгих окружений; non-root в образе; минимальный `env` браузера (без токенов раннера); `acceptDownloads: false`, без расширений, `--disable-dev-shm-usage` (Playwright), `--shm-size` в docker run; таймауты и лимиты памяти/pids контейнера; Chromium обновляется с каждым релизом Playwright (Renovate), ибо мы открываем недоверенные сайты. Документируем честно (Terra): контейнер — упаковка, не единственная граница; рекомендация — отдельный job без деплой-секретов/OIDC/Docker socket/SSH-агента; в Action — `permissions: contents: read` минимум; сборка/публикация отделены от сканирования.

**Сеть и SSRF — через egress-прокси, не через `route()`.** Собственный in-process forward-proxy (loopback, эфемерный порт, живёт только во время скана): для CONNECT и plain-HTTP резолвит хост **инжектируемым резолвером** один раз, проверяет каждый IP (loopback, private 10/8, 172.16/12, 192.168/16, link-local 169.254/16, IMDS 169.254.169.254 и `fd00::/8`, `::1`, `fe80::/10`, mapped-IPv4), отклоняет редиректы/фреймы/воркеры к таким адресам (проверка на каждое соединение, включая DNS-rebinding: соединяемся с проверенным IP, не повторно резолвим), применяет token-bucket на хост и считает запросы. Браузер (`proxy: { server }`) и undici (`ProxyAgent`) идут через него → политика едина, её нельзя обойти новым фреймом/воркером. `--allow-private` отключает фильтр для фикстур/внутренних сайтов. Цена: HTTP/3 отключается (фиксируется в Messumgebung), `response.serverAddr()` показывает прокси → IP берём из прокси (`connectedIp`). Расхожусь с engineering §6.5 (MVP-фильтр через `context.route`): `route` отключает кэш и не видит SW (browser §1.1) — конфликт, отмеченный критиком; прокси закрывает SSRF, лимиты и тест-карту хостов одним механизмом.

**XSS и инъекции в отчётах:** HTML без JS, CSP `default-src 'none'`, экранирование по умолчанию (Preact SSR), запрет `dangerouslySetInnerHTML`, URL текстом, тест «ноль сети/ноль CSP-нарушений»; тестовые строки вида `<script>`, `javascript:`, `"><img onerror`, bidi и ANSI в URL/именах cookies/заголовках/тексте страницы — обязательные фикстуры L1 для всех репортеров; консоль — очистка управляющих/bidi-символов; GitHub Job Summary — экранирование Markdown/HTML; `$GITHUB_OUTPUT` — только значения, контролируемые тулом; `::stop-commands::` для недоверенного вывода ⚠; JUnit — XML-построитель. Скриншоты — изображение, не DOM; PDF-рендер с `javaScriptEnabled: false`.

**Данные в отчётах:** минимизация по умолчанию (раздел 8 «что редактируется»); HAR/trace/полные URL — выключены, включаются явно с предупреждением о составе; `retention-days`/`expire_in` в шаблонах CI (30 дней по умолчанию); отчёты о чужих сайтах не публикуются публично (README, канарейка приватна); значения cookies/TC-String не хранятся (Breyer, IAB Europe — идентификаторы); Impressum-имена попадают в отчёт только как цитаты LEGAL-02 ≤ 300 символов; содержимое сайта не отправляется ни в какие внешние LLM/сервисы. Supply chain: пин зависимостей, `minimumReleaseAge`, загружаемые наборы данных валидируются zod и ограничены по размеру, никакой исполняемый код из данных/конфига сайта не выполняется в процессе сканера.

**Этика использования:** README-раздел «Bestimmungsgemäße Nutzung»: инструмент для собственных и мандатных сайтов; результаты — технические наблюдения, не Rechtsgutachten; Nutzungshinweis против массовых Abmahnungen (прецедент Google-Fonts-Welle); лицензия Apache-2.0 запретить использование не может — говорим об этом честно; CRA/PLD-статус проекта при монетизации заказчиком — на оценку юристу (раздел 14).

## 15. ADR-кандидаты

1. **ADR-0001 Стек и платформа** — TypeScript 7 + `playwright-core` 1.64.x (Chromium CfT new headless), Node ≥ 24 (CI 24/26), pnpm 11, Biome + oxlint-tsgolint, Vitest 5, zod 4 → JSON Schema 2020-12 + Ajv.
2. **ADR-0002 Конвейер и API проверки** — collectors → неизменяемый Snapshot v1 → чистые `Check.run` → observations → assess по ruleset → reporters; явный реестр в `src/checks/index.ts` + тест полноты; `--save/--from-snapshot`.
3. **ADR-0003 Профиль браузера** — свежий `launchPersistentContext(tmpdir)` на фазу (A/A′/B/C); пересмотр на `newContext()` только по данным калибровки.
4. **ADR-0004 User-Agent** — HTTP-пробы: токен + ссылка (ТЗ); браузер: профили `honest` (умолчание до калибровки) и `visitor` (чистый UA + заголовок `X-Dsgvo-Check`); обязательный детектор SCAN-BOTMODE; никакой подмены Client Hints/`webdriver`.
5. **ADR-0005 Exit-коды и статусы** — `0/1/2` по ТЗ; порог = primary-находки с `confidence ≥ high`; ошибка одной проверки → статус `error`, exit по порогу, `--strict` → 2; недоступность/блокировка/таймаут → 2; фатал приоритетнее порога; статусы `completed|partial|inconclusive|error|skipped|not_applicable` без `pass/fail`.
6. **ADR-0006 Пассивный режим** — три класса действий; лимиты (6 страниц, ≥ 1.5 с, ≤ 2 req/s, бюджеты DNS/HTTP/TLS); FILE-01/ADMIN-01 opt-in с фиксированными списками; TLS-04 = 2 handshake без завершения; robots для доп. страниц; non-features.
7. **ADR-0007 Модель уровней** — `severity` из `ruleset/de-2026.yaml` по `(checkId, class)`, не из кода; маппинг crmCode T0→critical, T1→critical-способный, T3→≤warning; `confidence` — отдельная ось; dedup «один факт → одна primary-находка».
8. **ADR-0008 Данные и лицензии** — в репо/образе только CC0/PDDL/MIT/Apache/CC BY; BY-SA/GPL opt-in в кэш; NC никогда; свой каталог сервисов из собственных аудитов (§ 87a); GeoIP off by default; owners/`reviewBy`/data-релизы.
9. **ADR-0009 CMP** — 7 собственных адаптеров с протоколом detect/state/firstLayer/reject/verify; autoconsent только детект/эвристика/справочник; вердикты CONSENT-04/05 только от адаптеров; эвристика → только `SCAN-BANNER-UNKNOWN` info.
10. **ADR-0010 Egress-прокси** — in-process forward-proxy для браузера и undici: IP-политика (SSRF/IMDS/rebinding), лимиты, счётчик, единая карта хостов в тестах; `route()` только в тестах; HTTP/3 отключён.
11. **ADR-0011 Контракт JSON** — `schemaVersion` semver независим от тула; правила minor/major; fingerprint `sha256(JCS({v,checkId,scope,key}))`; suppressions с `reason`+`expires`; `crmCode` nullable; открытые/закрытые enum.
12. **ADR-0012 Ожидание тишины** — свой алгоритм (`domcontentloaded` → `load` → MIN_DWELL/окно 2 с/inflight ≤ 1/HARD_CAP) вместо `networkidle`; параметры в конфиге, калибруются.
