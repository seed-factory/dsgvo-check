# 1. Позиционирование и границы

`dsgvo-check` — CLI для воспроизводимого сбора технических свидетельств о публичном немецком сайте и проверки их по настраиваемым правилам CI; он не устанавливает юридическую квалификацию и не сертифицирует соответствие DSGVO.

**MVP к релизу:** все 15 P0 из каталога, семь перечисленных CMP, JSON и консоль, HTML и PDF, `0/1/2`, GitHub Action, GitLab-шаблон, Docker и npm. Для проверки работоспособности отказа добавляю **CONSENT-05 из P1**: иначе инструмент покажет кнопку, но не сможет выполнить исходное обещание проверить, что меняется после отказа. Остальные P1/P2 — после P0, если хватает времени.

Расхождения разрешаю так:

- **PDF:** ТЗ требует JSON и консоль, HTML — если успеем; идея просит HTML/PDF. Принимаю HTML/PDF в объём этого проекта, но не называю их обязательными по ТЗ. PDF строится из того же локального HTML.
- **Код возврата:** в идее он опционален, в ТЗ обязателен. Реализуем и документируем как контракт.
- **FILE-01:** P2, не условие MVP. По умолчанию выключен; возможный будущий режим — только по явному opt-in и для разрешённого оператором scope. Сам флаг не заменяет разрешение владельца.
- **Передача за пределы ЕС:** география IP и сведения о предполагаемом получателе — разные технические признаки. Ни один из них сам по себе не доказывает международную передачу в юридическом смысле или её неправомерность. GeoIP — опциональное обогащение, не P0 и не причина автоматически повышать severity.

Не делаем авторизацию, отправку форм, сканирование всего сайта, обход CAPTCHA/бот-защиты, инъекции, эксплуатацию CVE, массовый перебор путей или юридические заключения. Результат относится только к наблюдённой выборке, среде и моменту времени.

Приоритет источников для реализации: явное решение в текущем запросе → ТЗ → каталог → идея → исследования. Несогласованную юридическую семантику фиксируем как вопрос заказчику, не выдавая её за установленный факт.

# 2. Архитектура

Конвейер:

```text
CLI/config → план скана и политика сети
           → browser / HTTP / TLS / DNS collectors
           → нормализация и редактирование
           → неизменяемый Snapshot + coverage
           → независимые Check → findings
           → дедупликация и baseline → JSON / console / HTML / PDF
           → вычисление exit code
```

Основные модули:

- **Orchestrator:** бюджет, состояние фаз, отмена, coverage и ошибки. Не содержит правил конкретных проверок.
- **Collectors:** браузерные события, DOM и доступный текст; HTTP-ответы и редиректы; TLS handshake; DNS. Управляющие CMP-адаптеры действуют только в браузерных сценариях.
- **Normalizer:** canonical URL, PSL, классификация сервисов и cookie, provenance данных, редактирование. Сохраняет различие между фактом и классификацией.
- **Policy/document extractor:** поиск и ограниченное извлечение Datenschutzerklärung и Impressum, нормализация текста и указание полноты.
- **Checks:** чистые функции от снимка и версионированного ruleset. Никаких сетевых запросов внутри проверок.
- **Finding engine:** стабильная идентичность, связанные находки, suppression, severity и `crmCode`.
- **Reporters:** получают одну и ту же модель; переводят `messageId` и параметры.
- **Network guard:** общая точка контроля соединений браузера и HTTP-клиента; ограничения ресурсов и scope.

Минимальный контракт:

```ts
interface Check {
  readonly id: string;
  readonly requires: readonly ArtifactKind[];
  evaluate(snapshot: Readonly<Snapshot>, rules: Readonly<Ruleset>): CheckResult;
}

interface CheckResult {
  status: "completed" | "partial" | "inconclusive" | "error" | "skipped";
  findings: readonly Finding[];
  coverage: readonly CoverageItem[];
}
```

Проверка добавляется как модуль с декларацией зависимостей и регистрируется автоматическим обнаружением файлов из фиксированной директории при сборке. CI проверяет уникальность ID, наличие текстов, `crmCode`, пары фикстур и корректность схемы. Ядро при добавлении проверки не меняется. Произвольное исполнение сторонних плагинов в MVP не обещаю; формат расширения отдельными пакетами — последующий ADR.

Данные живут отдельно от кода: `data/services`, `data/cookies`, `data/cmp`, `data/rules`, `data/messages/{de,en}`, `data/legal`, `data/licenses`. Каждый пакет имеет версию, источник, дату обновления и тесты. Правовые заметки — справочные, с датой экспертного ревью; они не подменяют доказательства.

# 3. Жизненный цикл скана и фазы согласия

**Выборка по умолчанию — до шести страниц контента**, включая входную: главная/входная, Kontakt, страницы с потенциальными формами или embed и другие уникальные same-origin ссылки по детерминированному приоритету. Impressum и Datenschutzerklärung открываются дополнительно как юридические документы, с отдельным лимитом на переходы. Каждую обнаруженную ссылку и причину выбора фиксируем. Ссылки на внешнюю политику открываем только при явном разрешении scope; иначе отмечаем неполное покрытие. На каждой выбранной странице проверяем доступность ссылок на документы. Это выборка, не утверждение «на каждой странице сайта».

**Три независимых сценария** с чистыми временными профилями:

1. **A, до действия:** открыть страницу, дождаться окна наблюдения, зафиксировать баннер, сеть и storage; не кликать.
2. **B, отказ:** в новом профиле повторить вход, сделать отказ через распознанный адаптер, проверить состояние и наблюдать последующие запросы; перезагрузить и проверить сохранение состояния.
3. **C, принятие:** в третьем профиле принять согласие и собрать сопоставимые наблюдения. Это контроль поведения, а не разрешение пользователю сканера действовать от имени посетителей.

Для B/C сначала принимаем решение на входной странице, затем посещаем ту же выборку; при разных CMP на отдельных страницах отмечаем границу действия решения. Никакое состояние A не переносится в B/C. По умолчанию использую полный Chromium в new headless и отдельный **persistent temporary profile** для каждого сценария; на эталонных сайтах сравнить с `newContext()`, поскольку влияние профиля на реальное поведение и сеть нужно измерить. Профили уничтожаются по завершении.

Ожидание: `DOMContentLoaded`, затем собственная тишина сети, например **2 секунды без новых релевантных запросов**, максимум **10 секунд на окно**; длинные WebSocket/SSE не удерживают окно открытым, но фиксируются. После этого один ограниченный scroll для lazy loading и ещё одно короткое окно. Отдельно фиксируем обрезанные long-polling, поздние события и таймауты. Стандартный `networkidle` не является доказательством завершения сайта.

Начальный бюджет: **180 секунд на скан**, 20 секунд на навигацию, до 3 редиректов на документ, максимум 600 исходящих запросов за скан; настройки раскрыть в отчёте. Навигации — не чаще одной в 1,5 секунды, собственные HTTP-пробы — не более 2/с на origin, ограничение параллелизма. Браузер может мгновенно породить много subresource-запросов: общий шлюз считает их и при превышении останавливает сбор; искусственное замедление ресурсов изменяет поведение, поэтому любые блокировки записываются в coverage. На `429/503` — backoff с ограничением и прекращение при повторении.

UA для **всех** запросов, включая браузер: честный `dsgvo-check/<version> (+https://github.com/<org>/dsgvo-check)` с фактическим публичным URL репозитория, определённым до релиза. Это требование ТЗ нельзя удовлетворить ссылкой только в HTTP-пробах. Если совместимость требует браузерный префикс, он должен отражать реально используемый Chromium; маскировку не применяем.

Геолокация определяется фактическим egress, а не `locale`: по умолчанию `de-DE`, `Europe/Berlin`, фиксированный viewport; страна egress — если установлена, с источником и датой. DE/EWR runner или разрешённый пользователем прокси рекомендуются для сопоставимых аудитов; местоположение не гарантируется. Challenge, признаки bot mode, авто-принятие CMP и подозрительно отличающиеся сценарии дают `inconclusive` для затронутых проверок, а не вывод об отсутствии баннера. Подтвердить реальные признаки на фикстурах и канарейке.

# 4. Баннеры и CMP

Адаптеры по порядку каталога: **Borlabs, Cookiebot, Complianz, Usercentrics, CCM19, Real Cookie Banner, CookieHub**. Каждый имеет versioned сигнатуры контейнера/iframe/shadow DOM, семантику кнопок первого уровня, методы отказа и принятия и необязательный считыватель документированного состояния. Использовать [autoconsent](https://github.com/duckduckgo/autoconsent) как источник исполняемых адаптеров под MPL-2.0, после проверки конкретного API и семи сценариев; отдельный слой оценивает первый уровень. Общий `optOut` не доказывает наличие равноценного отказа на первом экране.

Обобщённая эвристика ищет видимый dialog/overlay с лексикой cookies/privacy/consent и видимыми интерактивными кнопками, включая доступные iframe и shadow DOM. Для автоматического клика требуется **высокая уверенность**: контейнер и однозначная семантика действия, например score ≥0,9 и независимые признаки; порог и веса калибруются на размеченных фикстурах. Это инженерный порог, а не статистическая гарантия. Неоднозначную кнопку не нажимаем.

- CMP уверенно распознана, первичный экран наблюдаем: `CONSENT-04` оценивает видимую и работающую возможность отказа без дополнительного уровня; параметры сравнения доступности и формулировок согласуются с экспертом.
- Баннер не распознан или его наличие неопределённо: **`info` “Banner nicht erkannt”**, `CONSENT-04: inconclusive`; ложный `CONSENT-04` запрещён.
- Уверенно наблюдали страницу и нет видимого баннера, но есть определённые сервисы: возможна находка `CONSENT-03`; при bot/challenge/недостаточном наблюдении — только неопределённость.
- Проверка отказа: фиксируем нажатие, исчезновение/изменение баннера, доступное CMP/TCF-состояние, изменения storage и последующую сеть, затем reload. Закрытие баннера само по себе не означает отказ. Если состояние не читается, указываем косвенные признаки; запросы после отказа оценивает `CONSENT-05`.

# 5. Модель данных и контракт

Черновая форма JSON Schema: опубликованная схема задаёт обязательные поля, типы и ограничения; пример ниже показывает контракт, а не полную JSON Schema.

```json
{
  "schemaVersion": "1.0.0",
  "scannerVersion": "1.0.0",
  "ruleset": {"version": "2026.10.0", "dataVersions": {}, "rechtsstand": "2026-10-30", "profile": "de-default"},
  "scan": {
    "target": "https://example.de/",
    "startedAt": "2026-10-30T12:00:00Z",
    "durationMs": 43000,
    "browser": "Chromium …",
    "locale": "de-DE",
    "egressCountry": null,
    "limits": {},
    "status": "partial"
  },
  "coverage": [{"page": "https://example.de/", "phase": "before", "status": "completed", "reason": null}],
  "checks": [{"id": "CONSENT-01", "status": "completed", "reason": null}],
  "findings": [{
    "checkId": "CONSENT-01",
    "crmCode": "T1_TRACKER_BEFORE_CONSENT",
    "severity": "critical",
    "confidence": "high",
    "messageId": "consent.request.before",
    "params": {"service": "Example"},
    "fingerprintVersion": 1,
    "fingerprint": "sha256:…",
    "phase": "before",
    "page": "https://example.de/",
    "evidence": [{"type": "request", "url": "https://tracker.example/pixel", "method": "GET", "observedAt": "…", "redacted": true}],
    "relatedFindings": [],
    "suppression": null
  }],
  "errors": [],
  "disclaimerId": "technical-observations"
}
```

Evidence — типизированный union:

- `url`: очищенный URL, роль, redirect chain;
- `request`: очищенный URL, метод, инициатор, фаза, время и результат, если известен;
- `cookie`: имя, domain, path, атрибуты, источник/фаза; **без значения**;
- `header`: имя, безопасное значение либо факт наличия/отсутствия, URL;
- `dns`: имя, тип, нормализованная запись, resolver/время; `NXDOMAIN`, `NODATA`, `timeout`, `SERVFAIL` различаются;
- дополнительно `tls`, `textMatch`, `cmpAction`, `storage`, `dom` с ограниченными полями.

Все P0/P1 сохраняют точные `crmCode` каталога. Для P2, где они не указаны, `crmCode: null`; не придумываем CRM-коды. В evidence указываем источник и пределы, а в `confidence` — уверенность технического сопоставления, не вероятность нарушения закона.

`schemaVersion` независим от версии CLI: несовместимые изменения — major, совместимые необязательные поля — minor. Консьюмеры игнорируют неизвестные необязательные поля; новые enum-значения обрабатываются как неизвестные. Сортировка детерминированная.

Fingerprint v1 — SHA-256 канонического `checkId + origin + стабильный субъект + тип условия + значимый путь/фаза`, где субъект, например, имя заголовка, cookie name/domain/path или service ID. Не включаем время, текст перевода, значения cookie и случайные query. Несколько наблюдений одного условия объединяются в evidence; связанные `TRACK`, `CONSENT` и `EMBED` остаются отдельными ID без двойного подсчёта в сводке инцидентов. Baseline — опциональный файл с fingerprint, причиной, владельцем и сроком; подавленные находки остаются в JSON и не скрывают ошибки или неполное покрытие. Изменение алгоритма требует миграции baseline.

**Severity — приоритет технической реакции**, не юридический вывод. `info < warning < critical`; `--fail-on critical` — default, `--fail-on warning` включает и critical. «Превышен» в ТЗ трактуем как **достигнут или превышен**. Считаются только неподанvленные находки; `info` порог не достигает.

| Ситуация | Код |
|---|---:|
| Обязательная работа выполнена без ошибки исполнения и неподобранных находок на пороге | `0`, даже если есть явно показанный `inconclusive`, например неизвестный CMP |
| Есть непод подавленная находка на пороге | `1` |
| Неверные аргументы, сайт недоступен, не состоялся обязательный сбор, упал браузер или **хотя бы одна обязательная проверка завершилась `error`** | `2` |
| Одновременно находка на пороге и обязательная ошибка | `2`; findings сохраняются в частичном JSON |
| Неизвестный баннер | `info` и зависимые `inconclusive`; сам по себе `0`, но другие findings могут дать `1` |
| Таймаут всей загрузки входной страницы или обязательного collector | `2`; таймаут одного документа/фазы после успешного сбора — `partial`/`inconclusive`, если это ожидаемое ограничение; исключение исполнения обязательной проверки — `2` |
| Ошибка опциональной, выключенной или неприменимой проверки | Не влияет; если явно запущенная опциональная проверка упала, показываем ошибку и `2` |

Опциональный `--require-complete` может возвращать `2` за перечисленные в документации `partial/inconclusive`; неизвестный баннер при этом всё равно не становится ложным `CONSENT-04`. Это расширение семантики кода `2` требует согласования; default выше соответствует прямому требованию не превращать неизвестный баннер в нарушение.

# 6. Проверки

Обозначения: **A** — до действия, **B** — после отказа, **C** — после принятия, **H** — HTTP/TLS, **D** — DNS, **Doc** — документ. Severity — предлагаемый default технической политики, подлежащий экспертной вычитке. `crmCode` берётся буквально из каталога. «Doc: да» означает, что без доступной Datenschutzerklärung проверка неполна, а не чиста.

# 7. Данные и внешние источники

- **Сервисы:** собственный Apache-2.0 каталог целевых сервисов и endpoint, основанный на разрешённых аудитах и документации производителей; [third-party-web](https://github.com/patrickhulce/third-party-web) — дополнительный источник идентификации, при подтверждении лицензии конкретного snapshot. Категория домена не заменяет контекст запроса. Для cookies — Open Cookie Database, лицензия и происхождение конкретной версии **⚠ проверить** перед включением.
- **CMP:** [autoconsent, MPL-2.0](https://github.com/duckduckgo/autoconsent), с сохранением лицензий и исходников изменённых MPL-файлов; собственные семантические аннотации отдельно. Семь CMP нужно подтвердить исполняемыми тестами, а не только наличием имени в репозитории.
- **PSL:** `tldts` и включённый Public Suffix List, с соответствующими уведомлениями; private suffix policy фиксируется в ruleset.
- **GeoIP:** для MVP не обязателен. Опционально DB-IP Lite с атрибуцией CC BY 4.0, отдельной датой базы и явно ограниченной точностью; условия конкретной поставки **⚠ проверить**. Не включать GeoLite2 в неизменяемые артефакты без проверки EULA.
- **VULN:** для P1 выбираю локально обновляемые snapshots **OSV/GitHub Advisory Database** для поддерживаемых экосистем и **CISA KEV** для признака эксплуатации; Retire.js — для JS-компонентов. Фиксировать источники и атрибуции, проверять лицензии каждого набора и диапазоны версий перед поставкой. WordPress-покрытие через WPVulnerability — кандидат, но лицензия, полнота и право перераспространения конкретного feed **⚠ проверить**; если проверка не пройдена, не обещать покрытие плагинов. Не использовать WPScan как бесплатный коммерческий источник без разрешения.
- Ни один внешний сервис не получает URL проверяемого сайта автоматически. Обновление справочников — отдельная команда; отсутствие базы даёт `inconclusive`, а не «CVE не найдены». Все snapshots фиксируются по hash и дате.

NC-базы из ресёрча не включаем в коммерческий сценарий без отдельной лицензии. Не считаю утверждение «загрузка GPL-данных в runtime автоматически безопасна для Apache» установленным: совместимость и перераспространение требуют отдельного анализа.

# 8. Отчёты

Все форматы строятся из одного report model:

- **JSON:** полная структурированная версия, coverage, частичные ошибки, версии и redaction.
- **Консоль:** статус скана, покрытие, счётчики severity, краткие находки и путь к JSON; без цвета при `NO_COLOR` и в неинтерактивном CI.
- **HTML:** один самодостаточный файл, встроенные стили, без внешних ресурсов и чужого HTML/JS. Данные экранируются контекстно, ссылки допускают только безопасные схемы; CSP запрещает скрипты и внешние соединения.
- **PDF:** печать того же HTML через изолированный Playwright, с запретом сети, пригодными для печати таблицами и разрывами страниц.

Язык — `de` по умолчанию, `en` по выбору; машинные ID и evidence не переводятся. Немецкие тексты и дисклеймер предоставляет и утверждает заказчик; английские переводы проходят ту же проверку смысла. До утверждения тексты имеют статус черновика и блокируют релиз.

Пример дисклеймера для экспертной вычитки: «Dieser Bericht enthält technische Beobachtungen einer begrenzten automatisierten Prüfung. Er stellt keine Rechtsberatung und keine Feststellung der DSGVO-Konformität oder eines Rechtsverstoßes dar.»

**Редактирование до логов и сериализации:** значения cookies, Authorization, токены, тела POST, URL credentials, чувствительные query/path, персональные данные и секреты; сохранять минимальные разрешённые поля consent-состояния. Полный HAR, screenshots и trace по умолчанию не создаются. Hash значения cookie не считать анонимизацией. Доступ и срок хранения CI-артефактов настраиваются пользователем.

# 9. Тестирование

Для **каждой реализованной проверки**, включая P1/P2, обязательны минимум две авторские фикстуры: с конкретным наблюдаемым сигналом и без него. «Чистая» относится к этому сигналу, а не юридической чистоте сайта. Дополнительно — `inconclusive`, ошибка и контрпримеры там, где они влияют на вывод.

- **Unit:** чистые checks на записанных и обезличенных snapshots; таблицы алиасов/отрицаний, дедупликация, `crmCode`, схема, fingerprint и baseline. Для PRIV — собственные синтетические немецкие тексты, в том числе многостраничные, отрицания и неполные документы.
- **Browser integration:** локальные сайты, управляемые задержки, iframe/shadow DOM и семь минимальных CMP-фикстур; последовательности A/B/C, cookie, reload, поздние запросы, bot mode и неизвестный баннер. Проверять не только клик, но и реальное состояние и сеть.
- **Без интернета:** изолированная тестовая сеть с локальным DNS, доменами сайта и трекера, тестовым CA и локальными TLS-серверами с валидным, чужим, истёкшим сертификатом и HTTP redirect. Тестовый режим сетевой политики явно разрешает только эти адреса; настоящие внешние запросы запрещены. DNS-сервер воспроизводит NODATA/NXDOMAIN/SERVFAIL/timeout и наследование.
- **Контракт и безопасность:** golden JSON/HTML/PDF, проверка schema compatibility, все коды CLI, XSS-строки, redaction, DNS rebinding, redirects, IPv6/metadata и ограничения чтения. Smoke-test установленных npm/Docker/Action.
- **10 сайтов заказчика:** согласованный scope и частота, ручная разметка ожидаемых наблюдений, сравнение покрытия и расхождений. Это канарейка, не тест юридической истины и не замена локальным фикстурам.
- **Флейки:** фиксировать часы, браузер и версии данных; ожидать конкретные события и ограниченные окна, а не произвольные sleeps. Повтор разрешён для диагностики, но не превращает ошибку в молчаливый успех.

# 10. CI и дистрибуция

GitHub Action — Docker action для Linux с зафиксированным образом по digest; входы: URL, порог, формат и путь отчёта. GitLab — версионированный `include` с теми же входами. Docker — путь для остальных CI. npm-пакет публикует CLI и явные инструкции установки совместимого Chromium и системных зависимостей; «одна команда» работает после установки пакета и браузера.

Пример отдельного репозитория заказчика:

```yaml
name: privacy-scan
on: [push, workflow_dispatch]
permissions:
  contents: read
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Scan public site
        uses: example-org/dsgvo-check@<FULL_COMMIT_SHA>
        with:
          url: https://example.de
          fail-on: critical
          output: report.json
      - name: Preserve report
        if: always()
        uses: actions/upload-artifact@<FULL_COMMIT_SHA>
        with:
          name: dsgvo-report
          path: report.json
          retention-days: 7
```

На этапе 2 демонстрационный публичный тестовый сайт содержит известный сигнал, Action возвращает `1`, job краснеет, а артефакт доступен через `always()`. Плейсхолдеры заменяются реальными неизменяемыми SHA при публикации. Job не получает секреты и не делает checkout, если он не нужен.

Релизы из одного commit: SemVer CLI и отдельно schema/ruleset, changelog, npm provenance через trusted publishing при поддержке окружения, подпись OCI-образа и provenance/attestation, SBOM и проверка лицензий. Публикацию отделить от job, посещающего сайты; зависимости и Actions закреплять, выпускать регулярные обновления Chromium.

# 11. Безопасность и этика самого сканера

«Пассивный» здесь означает ограниченный неразрушающий аудит: обычные навигации, CMP-действия и описанные DNS/TLS/HTTP-пробы сами порождают трафик. Запрещены атаки, обход защиты, формы, аутентификация, автоматические претензии и использование найденных секретов.

Сайт исполняет недоверенный JS. Скан запускается в одноразовом изолированном runner/VM без секретов, cloud credentials, OIDC, Docker socket и чувствительных томов. Chromium — non-root, sandbox включён и проверен; ограничения CPU/RAM/PID/диска и времени. Docker сам по себе не является достаточной границей: [документация Playwright](https://playwright.dev/docs/docker) отдельно оговаривает риски недоверенных сайтов.

Для SSRF нужен egress enforcement **на каждом соединении** браузера и HTTP-клиента: локальный шлюз/прокси с проверкой разрешённого адреса при соединении, запрет loopback, private, link-local, metadata, IPv6 и DNS rebinding, включая redirects, iframe и workers. Прямой обход прокси, UDP/QUIC и другие сетевые пути должны блокироваться сетевой политикой окружения. Встроенный proxy без такой изоляции не является полной гарантией; MVP выпускается только после интеграционного подтверждения на поддерживаемых платформах. Локальные фикстуры используют отдельный изолированный режим.

`FILE-01` и `ADMIN-01` остаются выключенными по умолчанию. Отчёты считаются недоверенными: экранирование, безопасные ссылки, CSP, никакого исполнения чужих фрагментов; ограниченный доступ к артефактам и срок хранения.

# 12. План по этапам ТЗ 0–4

Оценка — **человеко-дни разработки и QA**, без календарного ожидания ревью и предоставления данных. Диапазон отражает риски CMP и изоляции; юридическая вычитка заказчика оценивается отдельно.

# 14. Решения за заказчиком

1. **Что означает `critical`?** A: юридически доказанное нарушение; B: уверенный технический сигнал высокого приоритета; C: любой потенциальный риск. **Рекомендация B**: автоматический сканер не устанавливает юридический состав.
2. **Какие запросы и cookies считать не-необходимыми для политики CI?** A: все третьи стороны; B: утверждённые сервисы и действия с исключениями; C: только известные tracking cookies. **B**, неизвестное отдельно.
3. **Consent Mode и cookieless pings:** A: автоматически допустимы; B: всегда critical; C: отдельный факт с контекстной оценкой. **C**.
4. **CONSENT-04:** A: только слово `Ablehnen`; B: понятный, доступный и работающий отказ на первом уровне с сопоставимой доступностью; C: полное визуальное равенство. **B**, с утверждёнными примерами, включая paywall и мобильный viewport.
5. **PRIV-01/02:** A: точное имя каждого сервиса обязательно; B: алиасы продукта/оператора и ручная оценка категориального описания и контекста; C: любое совпадение слова. **B**.
6. **Неполное покрытие в CI:** A: всегда `0` при отсутствии findings; B: default, описанный в разделе 5, плюс строгий opt-in; C: всегда `2` при любом `inconclusive`. **B**, с явной демонстрацией риска зелёного CI при неопределённости.
7. **Уровни HDR, Fonts, Maps, TLS и tracking:** принять предложенные технические defaults или предоставить собственную матрицу. **Рекомендация:** версия матрицы подписывается экспертом и хранится отдельно от кода.
8. **География и выборка:** A: любая среда; B: согласованный DE/EWR egress и выборка; C: весь сайт. **B**, поскольку полный охват без ограничений несовместим с бюджетом и воспроизводимостью.
9. **FILE/ADMIN:** A: на всех сайтах; B: opt-in на согласованном scope; C: исключить. **B**, после отдельного юридического ревью; для MVP не реализовывать.
10. **Документы и данные:** согласовать немецкие тексты, дисклеймер, владельцев/сроки хранения, публикацию результатов и допустимость внешней политики. **Рекомендация:** минимизированные приватные отчёты, raw-трассы выключены.
11. **P2 CRM:** предоставить `crmCode` либо официально разрешить `null`. **Рекомендация:** `null` до утверждения.

# 15. ADR-кандидаты

1. **Продукт и правовая граница:** технические наблюдения и политика CI без автоматической юридической квалификации.
2. **Релизный manifest:** все P0 и CONSENT-05; HTML/PDF включены как проектное решение сверх минимального ТЗ.
3. **Consent-сценарии:** три независимых чистых временных профиля A/B/C с проверкой сохранения отказа.
4. **Браузер:** полный Chromium new headless, честный UA и проверяемый sandbox.
5. **Coverage и exit:** отдельные статусы проверки; приоритет ошибки `2` над находкой `1`; неизвестный баннер сам по себе не ошибка.
6. **CMP:** versioned адаптеры и собственная семантика первого уровня; неопознанный баннер — `info`.
7. **Сетевой контроль:** принудительный egress на уровне соединений плюс изолированный runner; прямой обход шлюза закрыт.
8. **Пассивность и scope:** ограниченные публичные действия; FILE/ADMIN — отдельный opt-in только для разрешённого scope.
9. **Источники данных:** собственный каталог с разрешёнными snapshot-зависимостями, provenance и лицензионным учётом.
10. **JSON и baseline:** независимая версия схемы, типизированное evidence и версионированный fingerprint.
11. **Приватность evidence:** redaction до записи, без cookie values и raw trace по умолчанию.
12. **Поставка:** npm, подписанный OCI, Docker Action и GitLab include из одного проверенного commit.
13. **Качество:** две фикстуры на каждую проверку, тесты неопределённости и отдельная размеченная канарейка.
14. **Локализация:** утверждённые DE-тексты, эквивалентный EN и единая модель данных отчёта.

Прямое расхождение с частью ресёрча раунда 1: рекомендация убрать ссылку на репозиторий из браузерного UA ради обхода bot-детекта противоречит обязательному ТЗ и потому не принимается. Также вывод «одного `context.route()` достаточно для SSRF-защиты» не принимается: проверка DNS отдельно от фактического соединения оставляет проблему rebinding и не охватывает все сетевые пути. Предложение обнаруживать mixed content только по сетевым событиям недостаточно: Chromium может заблокировать или автоматически обновить ресурс до наблюдаемого запроса.
