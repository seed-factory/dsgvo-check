# Architecture Decision Records — dsgvo-check

Этот каталог хранит архитектурные решения проекта в кратком формате MADR: по файлу на решение, с контекстом, рассмотренными вариантами и последствиями. Он нужен разработке, чтобы не переоткрывать закрытые споры, и заказчику, чтобы видеть, какие решения ждут его ответа. Источник решений — [итог консенсуса](../consensus/README.md) с поправками раунда 4б ([errata](../consensus/round-4/errata.md)); при расхождении прав консенсус, при расхождении с [ТЗ](../../specs/dsgvo-check_TZ.md) — ТЗ.

## Формат

- Имя файла `NNNN-kebab-case-title.md`, нумерация с 0001.
- Разделы: Статус, Контекст, Решение, Рассмотренные варианты (плюс и минус каждого), Последствия, Ссылки.
- Статус `Accepted` — решение принято консенсусом или заказчиком. `Proposed` — решение ждёт ответа заказчика; запись называет номер вопроса из [раздела 8 консенсуса](../consensus/README.md#8-вопросы-заказчику). До ответа разработка следует рекомендации панели, а если она отходит от ТЗ — букве ТЗ.
- Пометка «⚠ проверить, факт N» отсылает к [непроверенным фактам](../consensus/README.md#7-непроверенные-факты).

Кандидаты, ещё не оформленные отдельными записями (решения действуют по консенсусу): ADR-009 «Версионирование» ([§5.6](../consensus/README.md#56-crmcode-и-версии)), ADR-018 «Документный конвейер» (D15), ADR-020 «VULN» — правило `critical` (D17), ADR-022 «Ruleset» (D19, D22), ADR-024 «Тексты и i18n» (D22), ADR-031 «Тестирование» (D23), ADR-032 «Форматы отчёта» (D02, полная CSP — в [0016](0016-isolation-sandbox-and-egress-proxy.md), маппинг JUnit — в [0005](0005-result-model.md)), ADR-033 «Релизы и supply chain» (предложение модератора к этапу 4, в раунде 3 не голосовалось). Следующие номера — с 0020.

## Как добавить запись

1. Взять следующий номер, скопировать структуру любой записи.
2. Указать статус и, для `Proposed`, номер вопроса заказчику.
3. В «Ссылках» дать относительные ссылки на консенсус, предложения раунда 2, критику раунда 3 и ресёрч.
4. Добавить строку в индекс выше.
